## 1 背景

巡查人员是环卫作业中的重要一环，主要是对作业后的路面进行质量检查，其作业模式一般采用巡查人员在收到巡查任务后，搭载机动车或者电瓶车等进行巡查，在这其中可能会发现质量事件，则进行事件上报，派发至相关责任人进行处置。目前巡查人员主要通过对讲机、微信等的形式进行事件上报，尚未完整的巡查数字化体系

本应用主要针对巡查人员采用手机端进行巡查的场景，该类场景中，巡查人员可能通过手机端应用单独完成巡查任务和事件上报，也可能与车机端应用进行协同任务。

## 3 产品定义与说明
### 3.1 产品定义

品质巡查移动端主要涉及两个部分内容，一个是手机移动端品质巡查应用，一个是车机端品质巡查应用。

**手机移动端品质巡查应用：** 作为品质巡查的主要移动载体，其中不仅涉及到巡查任务的具体执行，还会涉及到巡查人员这一角色的其他常用功能，如水电油上报等，支持通过扫码的方式完成用户登录，使得手机移动端与车机端应用的任务与事件信息互通

**车机端品质巡查应用：** 考虑到机动车安全事件，因此如果是机动车巡查，在车机中集成此 APP，主要聚焦于执行任务的实时显示和事件查看，并搭配车辆套件进行事件的上报。该应用按照 16:9 的尺寸设计。

## 4 流程 + 规则 + 状态
### 4.1 巡查任务状态机

任务状态机与常规任务、动态任务相同

| **状态名称** | **业务释义**                                                 | 是否终态 |
| -------- | -------------------------------------------------------- | ---- |
| 待下发      | 云端创建任务，保存，尚未推送车辆/APP                                     | 否    |
| 待接收      | 云端已下发任务；等待目标司机在 APP 确认接收                                 | 否    |
| 进行中      | 正式启动作业，正在执行清扫任务                                          | 否    |
| 已完成      | 任务正常跑完，作业闭环                                              | 是    |
| 已转派      | 原接收方发起转派，等待新目标接收                                         | 否    |
| 已终止      | 管理员云端/APP 人工强制终止任务，非正常闭环；<br><br>进行中超时未上报完成，系统自动终止，非正常闭环 | 是    |
| 已失效      | 超时无人接收、车辆离线无法执行，任务超过最晚可开始时间没开始，自动失效                      | 是    |

### 4.2 事件状态机

事件上报后会进入到动态任务池中，并进行下一步流转，因此其状态参照动态任务的状态机，以环卫云平台中提供的状态机为准

待判别、待分配、待处理、处理中、待核查、已完成

### 4.3 校验规则

以下校验规则依赖环卫云平台中的规则配置功能，服务由环卫云平台提供，用户可在环卫云平台中根据项目需求进行自主配置。在环卫云平台相关功能尚未完善的前提下，可暂不开发，予以保留相关接口即可。

**绑车前校验**

如果用户未执行绑定车辆操作，则无需此校验

| -------- | ----------------------------- | ------------------------------------------------------- | ------ |

| 车辆在线状态校验 | 当前车辆网联装置在线                    | toast 提示：“当前车辆网联装置离线，请检查”                               | 可进入下一步 |

## 6 移动端应用功能需求

移动端品质巡查应用内容与车机 APP 内容差不多，区别在于移动端应用能够支持事件的上报，也能通过扫码的方式登录车机 APP。此外，移动端应用不仅仅是移动的执行工具，还承载了巡查人员相关的其他功能。

### 6.1 地图 tab 页

地图 tab 页是品质巡查应用的默认首页，主要是通过地图承载巡查任务、事件，支撑巡查人员的日常工作

#### 6.1.1 任务卡片
1. 初次进入模块后，此时还没有开始的任务
	- 底部显示任务卡片，默认显示该用户时间排序最早的任务
	- 地图中默认显示选中任务对应任务的作业区域、用户手机 APP 位置、当前车辆位置（如有绑定车辆）、以及对应轨迹、事件点位。图层优先级依次递增
		- 任务区域的颜色按照任务的状态显示不同的颜色，包括待接收、进行中、已完成和其他（已终止、已转派、已失效）
2. 底部任务卡片上方显示车辆连接信息。
	- 未连接：点击后打开扫描二维码功能
	- 已连接：展示已连接的车牌号，点击可打开连接信息
		- 车牌号
		- 连接状态
		- 绑定事件
		- 断开连接按钮：点击后能够在手机移动端主动退出登录车机端 APP，需二次确认
3. 任务卡片中显示选中的任务的主要信息，包括区域名称、计划时间、类型、要求等。
	- 巡查任务
		- 片区名称 - 事件上报数（如果任务未开始，则不显示该信息）- 任务状态
		- 任务日期 - 作业时间 - 作业资源
		- 开始时间：HH:MM
		- 作业里程：单位 km，保留 2 位小数，计算开始任务时间到当前时间的轨迹长度
		- 作业时长：单位为分钟，保留整数，当前时间 - 开始任务时间
4. 任务卡片中有以下按钮：
	- 开始任务：点击后进入需要校验是否满足开始任务条件，具体参 4.3 章节。
	- 任务详情：次按钮，点击后打开对应任务详情页面，查看详细要求
	- ***更多按钮**（不在本期范围内）：点击后显示暂停任务、转派任务、关闭任务按钮*
		- *暂停任务：将当前正在进行中的任务暂停，在此状态下，用户可以开始执行其他任务*
		- *转派任务：点击后将当前任务移交给其他人*
		- *关闭任务：将选中的任务予以关闭*

5. 支持向上拉起打开今日待办任务清单，显示全部该人员的今日待办任务（可覆盖地图，也支持收起），也可以通过点击“今日任务”按钮达到相同的效果。
6. 今日待办任务清单顶部按照待接收、进行中、已完成进行分组统计。已完成任务统一移动至组内列表底部。
	- 存在进行中任务 → 默认选中进行中任务。
	- 无待办任务 → 展示空任务状态。
7.  用户在今日待办任务清单选中某任务时，地图上显示该任务计划区域信息，任务卡片变为该任务的详细信息
8. 用户点击开始任务按钮，系统校验通过后，任务开始，进入任务执行状态。此时收起今日待办任务清单
9. 任务执行状态下
	- 任务卡片变为收起状态，仅展示片区名称和开始时间、作业里程、作业时长
	- 地图上显示任务的计划区域信息、手机的实际轨迹、车辆实际轨迹（如有）、手机实时位置、车辆实时位置（如有）、事件上报点位，图层优先级递增。
	- 结束任务按钮：圆形大按钮，显示在页面底部，点击后先进行二次确认，再进行**任务完成情况校验**，通过后结束任务
	- 事件上报：圆形大按钮，显示在页面底部，点击后自动触发摄像头进行拍照，拍照完成后打开事件上报页面，照片自动上传事件照片字段
10. 用户在地图模块，若收到新派发的任务，在地图上方 banner 提示，信息靠左排列，默认显示时间为 1min。并支持进行语音播放，
	- 对于接收到的属于该用户的新任务，播放与展示内容：新任务【作业类型】-【任务区域】-【任务计划时间】
	- *对于其他消息，按照推送的内容播放与展示。（暂无其他消息，在此仅做预留）*
11. 用户在地图中点击事件点位图标，打开对应事件详情
12. 地图右侧有辅助按钮：
	- 今日事件：角标显示该用户关联的任务上报的事件总数，点击图标打开今日上报事件清单
	- 今日任务：角标显示当天任务数，点击图标打开今日任务清单
	- 复位：点击后地图焦点回到当前人员位置
	- 图层：与用车管理模块相同
	- 图例：点击控制图例的显隐

13. 点击返回按钮
	- 如果此时正在执行任务，toast 提示：“当前有进行中任务，退出后仍会继续：。返回上一页
	- 如果此时没有进行中任务，直接返回上一页
#### 6.1.2 今日任务清单
1. 触发条件：点击“今日任务”按钮，呈选中状态
2. 默认展示当前用户今天的所有的巡查任务，并按照任务状态进行分组，优先级依次为：待接收>进行中>已完成>已转派>已终止>已失效。若某一分组内无数据，可不显示该分组。分组内按照计划作业时间按顺序排列
3. 任务卡片显示信息：
	- 片区名称 - 事件上报数（如果任务未开始，则不显示该信息）- 任务状态
	- 任务日期 - 作业时间 - 作业资源
4. 点击卡片，地图聚焦展示该任务区域、事件点位（如有），底部任务卡片展示任务信息
5. 点击详情，打开任务详情页面，展示信息如下
	- 顶部为地图，地图中展示任务区域范围
	- 标题摘要
		- 片区名称 - 事件上报数（如果任务未开始，则不显示该信息）- 任务状态
		- 任务日期 - 作业时间 - 作业资源
	- 任务信息
		- 任务编号
	- 任务执行信息：（如果任务为待接收状态，无需显示该信息）
		- 开始时间：任务开始的时间
		- 作业里程：任务过程中的里程数，按照手机的轨迹里程计算，单位 km，保留 2 位小数
		- 作业时长：结束任务时间或者当前时间 - 开始时间，单位 min，保留整数
	- 事件上报列表：展示该任务关联的事件列表，列表中的事件卡片支持点击交互，点击后打开对应事件详情
	3. 底部操作栏：返回

#### 6.1.3 今日事件上报清单
1. 触发条件：点击“今日事件”按钮，呈选中状态
2. 默认展示当前用户今天的所有的巡查任务中关联的事件列表，并按照事件状态进行分组
3. 事件卡片显示信息：
	- 上报时间 - 事件地点
	- 事件发现类型 - 事件状态
	- 事件描述
4. 点击卡片，地图聚焦该事件点位，呈选中状态；再次点击卡片，可以取消选中卡片，地图取消点位选中效果
5. 点击详情按钮，打开事件详情页面，展示信息如下
	- 顶部为地图，地图中展示事件点位
	- 标题摘要
		- 问题类型、事件发生时间、事件状态
		- 事件发现类型：AI、人工，人工触发方式的为人工，其余全部记为 AI
		- 事件来源：监控中心、机器人采样、AI 监控采样、对讲机采样、无人机采样、车载监控采样 (巡查车属于这一类)、第三方
		- 事件发现方：具体的人、车，如巡查员张三、独角兽 10032、摄像头 A
	- 事件信息
		- 任务编号
		- 经纬度
		- 事件地点
		- 事件图片
		- 事件描述
	- 处置节点，高亮展示当前节点
		- 待判别 - 待分配 - 待处理 - 处理中 - 待核查 - 已完成
	3. 底部操作栏：返回
#### 6.1.4 事件上报页面

1. 事件上报页面包含以下信息：

- 事件发生时间：自动获取，必填
- 经纬度：自动获取手机当前位置，必填

### 6.2 服务页面
#### 6.2.1 框架

按照业务分组的方式对品质巡查管理模块进行分组。

1. 品质管理：面向品质巡查这一业务，分为巡查任务、品质事件
2. 车务管理：目前主要针对能耗类费用数据上报和记录查看，分为加油上报、加水上报、充电上报、上报记录，可直接复用水电油上报的内容
3. 维保管理：支持用户进行车辆故障报修和维修记录查看；（不在本次范围内）
4. 数据统计：以用户为维度进行事件上报、任务等数据统计；（不在本次范围内）
后续可能会根据实际情况对分组进行重新组织或更新
#### 6.2.2 项目切换功能
1. 显示用户当前登录的项目名称，该项目名称与用户在功能操作时能够看到的数据资源关联
2. 默认显示为最近一次使用的项目，点击项目名称后弹出项目选取列表（当前用户关联的项目），支持搜索项目名称
#### 6.2.3 巡查任务
1. 按照任务状态进行分组展示，分为待接收、进行中和已结束三个 tab 页。默认选中待开始
	- 其中已结束中包含这几类任务状态的任务：已完成、已转派、已终止、已失效
2. 筛选条件
	- 日期筛选，默认选中今天，支持今天、明天、近七天、全部、自定义时间段搜索，该日期指的是任务计划执行的日期
3. 卡片样式：
	- 片区名称 - 事件上报数（如果任务未开始，则不显示该信息）- 任务状态
	- 任务日期 - 作业时间 - 作业资源
4. 点击卡片，打开任务详情页。任务详情页同 6.1.2 章节内容。底部不支持开始任务/结束任务功能，支持和返回上一页
#### 6.2.4 品质事件
1. 按照事件状态进行分组展示，分为待判别、待分配、待处理和已完成 4 个 tab 页。默认选中待处理
	- 待判别：待判别
	- 待确认：待分配
	- 待处理：包括待处理、处理中、待核查
	- 已完成：已完成
2. 筛选条件
	- 日期筛选，默认选中今天，支持今天、明天、近七天、全部、自定义时间段搜索，该日期指的是任务计划执行的日期
3. 卡片样式：
	- 上报时间 - 事件地点
	- 事件发现类型 - 事件状态
	- 事件描述
4. 点击卡片，打开事件详情页。详情页同 6.1.3 章节内容。
