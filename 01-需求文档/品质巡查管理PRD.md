# 名词解释
## 1 背景

巡查人员是环卫作业中的重要一环，主要是对作业后的路面进行质量检查，其作业模式一般采用巡查人员在收到巡查任务后，搭载机动车或者电瓶车等进行巡查，在这其中可能会发现质量问题，则进行事件上报，派发至相关责任人进行处置。目前巡查人员主要通过对讲机、微信等的形式进行问题上报，尚未完整的巡查数字化体系

## 2 主要角色与权限

### 2.1 角色划分

| 角色         | 职责                         | 备注                           |
| :--------- | :------------------------- | :--------------------------- |
| 巡查员 - 机动车  | 巡查任务、任务执行、水电油上报、故障报修、数据统计等 | 涉及到与机动车相关的车务信息，以及与车机 APP 的联动 |
| 巡查员 - 非机动车 | 巡查任务、任务执行、问题上报、数据统计等       | 仅适用移动 APP                    |

### 2.2 功能权限

对于移动 APP，巡查员 - 机动车、巡查员 -非机动车拥有对应应用的全部功能权限

### 2.3 数据权限

本应用结合实际业务场景，按照项目制来进行业务的开展，因此所有的数据权限都基于项目范围内获取。

巡查员 - 机动车、巡查员 - 非机动车均能查看本人相关的所有任务记录和问题信息

## 3 产品定义与说明
### 3.1 产品定义

品质巡查移动端主要涉及两个部分内容，一个是手机移动端，一个是车机端。

手机移动端：作为品质巡查的主要移动载体，其中不仅涉及到巡查任务的具体执行，还会涉及到巡查人员这一角色的所有功能，本质上与车机端是两个载体，一套数据库

车机端：考虑到机动车安全问题，因此如果是机动车巡查，拟在车机中集成此 APP，主要聚焦于执行任务的实时显示和问题查看。

### 3.2 与现有系统的关系

| 系统名称  | 关系                   | 备注  |
| ----- | -------------------- | --- |
| 环卫云平台 | 进行巡查任务的制定与派发，问题的闭环处置 |     |

## 4 流程 + 规则 + 状态
### 4.1 巡查任务状态机

任务状态机与常规任务、动态任务相同

### 4.2 问题状态机

以环卫云平台中提供的状态机为准

待确认：问题上报的初始状态

待分配：待分配给具体责任人

待处理：已分配责任人，待返回处理结果

已完成：已返回处理结果

## 6 移动 APP-非机动车寻擦汗

移动 APP 的架构与驾驶员的用车管理应用整体相同，只是因为用户角色的不同，导致的功能存在部分差异。

### 6.1 地图 tab 页

与用车管理类似，移除顶部的车辆绑定的信息栏，仅保留地图和任务卡片、任务列表模块

#### 6.1.1 地图页面
1. 初次进入模块后，此时还没有开始的任务
	- 底部显示任务卡片，默认显示该用户时间排序最早的任务
	- 地图中默认显示当前人员位置 + 任务卡片中的任务计划区域 + 重点点位（如有）
2. 任务卡片中显示选中的任务的主要信息，包括区域名称、计划时间、类型、要求等。
	- 巡查任务
		- 区域名称 - 任务状态
		- 任务类型 - 作业类型 - 计划时间段
		- 开始任务时间：HH:MM
		- 作业里程：单位 km，保留 2位小数，计算开始任务时间到当前时间的轨迹长度
		- 作业时长：单位为分钟，保留整数，当前时间 - 开始任务时间
		- 问题上报数：本次任务上报的问题数，支持点击，点击后打开问题列表
3. 任务卡片中有以下按钮：
	- 开始任务：点击后进入需要校验是否满足开始任务条件。满足以下校验条件后，toast 提示：任务已开始。进入任务执行
		- 校验当前时间是否在允许开始时间范围内：阻断项
		- 是否有其他正在执行的任务：若校验失败，toast 提示“当前存在进行中任务”，任务卡片跳转为正在进行中的任务。阻断项
		- 校验人员的位置是否在路段范围：阻断项
	- 任务详情：次按钮，点击后打开对应任务详情页面，查看详细要求
	- ***更多按钮**（不在本期范围内）：点击后显示暂停任务、转派任务、关闭任务按钮*
		- *暂停任务：将当前正在进行中的任务暂停，在此状态下，用户可以开始执行其他任务*
		- *转派任务：点击后将当前任务移交给其他人*
		- *关闭任务：将选中的任务予以关闭*

4. 支持向上拉起打开今日待办任务清单，显示全部该人员的今日待办任务（可覆盖地图，也支持收起），也可以通过点击任务卡片下方“今日任务 X 项”达到相同的效果。
5. 今日待办任务清单顶部按照未完成、进行中、已完成进行分组统计。已完成任务统一移动至组内列表底部。
	- 存在进行中任务 → 默认选中进行中任务。
	- 无待办任务 → 展示空任务状态。
6.  用户在今日待办任务清单选中某任务时，地图上显示该任务计划区域信息，任务卡片变为该任务的详细信息
7. 用户点击开始任务按钮，系统校验通过后，任务开始，进入任务执行状态。此时收起今日待办任务清单
8. 任务执行状态下
	- 任务卡片变为收起状态，仅展示任务名称和开始时间、作业里程、已作业时长，不需要占据过大面积
	- 地图上显示任务的计划区域信息（淡蓝色填充虚线）、重点点位人员的实际移动轨迹（红色实线）、人员位置、问题上报点位，图层优先级递增。人员位置点实时刷新
	- 结束任务按钮：圆形大按钮，显示在页面底部，点击后进行**任务完成情况校验**，通过后结束任务
	- 问题上报：圆形大按钮，显示在页面底部，点击后自动触发摄像头进行拍照，拍照完成后打开问题上报页面
9. 用户在地图模块，若收到新派发的巡查任务：
	- 轻提醒 → 地图上方 banner 提示，信息靠左排列，内容格式为“任务类型 任务名称 距离 ”，默认显示时间为 1min
	- 语音播报任务信息：收到新的【任务类型】，【任务标题】
	- 右侧固定“查看”按钮，点击后，展开今日待办任务清单，并选中该任务
10. 用户在地图中点击问题点位图标，打开问题详情
11. 用户点击辅助按钮：
	- 问题数：角标显示当前任务上报的问题数，点击图标打开问题记录页面，并筛选相应问题记录
	- 复位：点击后地图焦点回到当前人员位置
	- 图层：与用车管理模块相同
12. 点击返回按钮
	- 如果此时正在执行任务，toast 提示：“当前有进行中任务，退出后仍会继续：。返回上一页
	- 如果此时没有进行中任务，直接返回上一页
#### 6.1.2 问题上报页面

1. 问题上报页面包含以下信息：
- 问题编号：自动生成，必填
- 问题上报时间：自动获取，必填
- 问题经纬度：自动获取手机当前位置，必填
- 问题位置：自动获取手机当前位置，必填
- 问题照片：必填，仅支持拍照上传，上限 5 张
- 问题描述：支持手写和语音输入，200 字，非必填
- 备注：非必填，200 字
说明：问题上报后的流转、处置等流程均有环卫云开展，APP 暂不涉及
2. 底部操作按钮：
	- 提交
	- 取消

### 6.2 服务页面
#### 6.2.1 框架

按照业务分组的方式对品质巡查管理模块进行分组。

1. 任务管理：针对用户收到的不同类型任务进行分组展示，目前仅展示巡查任务
2. 问题与事件：展示用户收到的不同问题与事件
3. 车务管理：目前主要针对能耗类费用数据上报，分为加油上报、加水上报、充电上报，支持查看已上报的记录，该模块仅对巡查员 - 机动车角色展示
4. 维保管理：支持用户进行车辆故障报修和维修记录查看；（不在本次范围内）
5. 数据统计：以用户为维度进行问题上报、任务等数据统计；（不在本次范围内）
后续可能会根据实际情况对分组进行重新组织或更新
#### 6.2.2 问题记录

2. 筛选条件
	- 日期筛选，默认选中今天，支持今天、明天、近七天、全部、自定义时间段搜索，该日期指的是任务计划执行的日期
3. 卡片样式：
	- 问题编号 - 问题状态
	- 问题位置
	- 当前节点
4. 点击卡片，打开问题详情页。
#### 6.2.3 问题详情页
##### 6.2.3.1 顶部地图

顶部为地图，地图中展示问题点位

#### 6.2.4 详细信息

1. 标题摘要
	- 问题编号、问题状态
2. 问题信息
	- 问题上报时间
	- 问题经纬度
	- 问题位置
	- 问题照片
	- 问题描述
	- 备注
3. 处置节点图：分为待确认 - 待分配 - 待处理 - 已完成
4. 问题处置信息
	- 处置人员
	- 处置完成时间
	- 处置后照片
	- 备注
5. 底部操作栏：返回

## 7 车机 APP

车机 APP 是巡查人员 - 机动车的主要任务执行页面。其界面尺寸按照 16:9 进行设计

### 7.1 车辆绑定/交车页面

车辆的绑定/交车实际是与车机 APP 的登录是关联的，车机查询的任务时当前车辆绑定的用户的巡查任务。

#### 7.1.1 车辆绑定页
1. 在车机未绑定用户下，打开应用后则显示车辆二维码页面，二维码顶部为绑车说明
2. 用户使用移动 APP 扫码成功后，进行**人车关系校验**
	- 校验通过，完成用户与车辆的使用关系绑定
	- 校验不通过，toast 提示失败原因
3. 扫码完成后系统记录人员 + 时间 + 车辆 + 位置信息

#### 7.1.2 交车页
1. 车机已绑定车辆下，用户点击交车按钮，进行**未完成任务校验**，
	- 校验通过，打开二维码页面，二维码顶部为交车说明
	- 校验不通过，toast 提示：存在进行中任务，无法交车
2. 用户使用移动 APP 扫码完成后系统记录人员 + 时间 + 车辆 + 位置信息，并解除人与车使用关系的绑定
3. 打开今日回顾页面
### 7.2 系统首页

扫码成功后，进入系统首页，首页是用户的主要操作界面，采用左右分屏设计

**左屏——地图**

地图中默认显示默认选中任务的作业区域、重点点位和当前车辆位置。

地图右侧中有以下工具按钮：

- 复位：回正到车辆当前位置
- 图层：辅助设施图层（图层点位及功能与用车管理地图页面中的一致）
- 全屏：地图全屏展示
- 交车：解除人车绑定关系（仅在已绑定车辆状态下才会显示）
**右屏——任务列表
1. 默认展示该用户今日的所有任务，并按照计划时间顺序排列，任务显示信息包括
	- 巡查区域-任务状态
	- 任务类型 - 计划时间段
2. 同一状态的任务按照计划时间排序，不同状态的任务优先级分别为进行中>待开始>已完成，即已完成的任务自动移动至列表底部
3. 点击任务卡片显示具体任务信息
	- 区域名称 - 任务状态
	- 任务类型 - 计划时间段
	- 开始任务时间
	- 作业里程
	- 作业时长
	- 问题上报数
	- 问题列表卡片
4. 任务信息底部有以下按钮：
	- 开始任务：针对待开始任务
	- 结束任务：针对进行中任务

### 7.3 任务执行页面
1. 点击开始任务后，需要校验是否满足开始任务条件。若满足开始任务条件，则进入到任务执行页面
	- 一次只能有一条正在执行中的任务
2. 左侧地图会展示车辆的实时轨迹和上报的问题点位，右侧列表会展示当前任务的基本信息，及实时更新的问题卡片列表，按照上报时间倒序排列
3. 问题卡片中包含信息：
	- 问题编号
	- 问题状态：待确认、待分配、待处理、已完成
	- 问题位置
	- 问题上报时间
	- 问题照片
4. 用户点击地图问题点位或者问题卡片，能够查看问题详情，详情中会展示问题的信息及处理结果、处理日志，具体参考6.2.3章节内容
>	说明：车机 APP 不负责问题的上报，问题上报由车载外设装置进行，并由 t-box 上传到云端，生成问题，车机 APP 仅负责任务的执行与问题的展示
5. 用户在行驶过程中如果收到新的任务，则在地图上方显示 banner 轻提醒，并进行语音播放，播放内容：收到新的任务，【任务类型】-【任务区域】-【任务计划时间】
6. 用户点击“结束任务”，点击后进行**任务完成情况校验**，若通过，则完成任务。
	- 若当前用户中有待开始的任务，则 toast 提示：已结束当前任务，已自动推送下一条。地图和任务卡片效果等同于选中该任务
	- 若均无待开始任务，则 toast 提示：今日任务均已完成，可在归还车辆后交车
7. 用户点击地图右侧“交车”按钮，点击后先进行**未完成任务校验**，若通过，则
	 - 当前仍存在进行中未结束任务：无法交车。地图和任务卡片中显示该任务信息
	- 校验通过，则打开“交车”页面由用户进行扫码交车
8. 交车成功后，打开今日回顾页
	- 展示任务完成数、轨迹里程、出车时长、问题上报数（指该用户通过外设上报的问题数）。时间范围均限制在当日
	- 展示用户今日未完成的巡查任务
	- 展示用户明日的待办巡查任务

## 8 待确认问题

#### 8.1.1 巡查人员 - 机动车

巡查人员 - 机动车巡查的模式，其 APP 应用界面基本与司机用车管理页面一致，主要有以下几点不同：

1. 接收的任务类型为巡查任务，其任务卡片内容有所变化：
	- 巡查任务
		- 区域名称 - 任务状态
		- 任务类型 - 作业类型 - 计划时间段
		- 开始任务时间：HH:MM
		- 作业里程：单位 km，保留 2 为小数，计算开始任务时间到当前时间的轨迹长度
