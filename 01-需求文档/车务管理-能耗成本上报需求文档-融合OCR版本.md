## 1 背景

 公司目前有大量的车辆在运营中，包括自研的车辆和外采的车辆，这些车辆在运行过程中会产生能耗费用，包括油、电、水等类型。目前这些数据并未有标准化的线上采集流程，导致单车的能耗费用数据难以精准收集。因此，基于酷哇 APP 这一平台，围绕着车辆能耗成本的线上登记，进行能耗管理的需求分析与功能设计。

## 4 产品定义与说明

### 4.1 产品定义

本功能主要搭载在两个端，移动端和 WEB 端

**移动端：**

1. 移动端主要搭载在酷哇 APP 工作台中，搭载在用车管理 - 车务管理应用中。
2. 该应用支撑司机等角色进行现场的加油、充电、加水信息和费用上报，支持查看已填报的记录；支持查看已填报的记录
3. 推荐采用 OCR 技术实现加油交易凭证、里程表、充电明细截图等的自动识别，具体实现需要技术验证

**WEB 端：**

1. WEB 端按照搭载在环卫云考虑，按照单个项目维度来查看数据

### 4.2 与现有系统的关系

| 系统名称     | 关系                           | 备注      |
| -------- | ---------------------------- | ------- |
| 酷哇 APP   | 移动端的搭载平台，功能放置在城市管家 - 车务管理应用中 |         |
| 车辆管理系统   | WEB 端的搭载平台，功能放置在费用管理模块中      |         |
| basis 平台 | 从 basis 平台中接入车辆信息、车型信息、项目信息  |         |
| 权限系统     | 调用权限和用户信息                    |         |

### 4.3 产品边界

1. 本应用无法支持采集的场景为：
	- 独家兽之家等无法区分单车电量、无单次电费单价的充电费用录入
	- 外租场地用水等无法区分单车水量、无用水单价、无单次用水金额的加水费用录入
2. 可不采用本 APP 上报的场景为：
	- 采用统一充电卡进行充电时，由于可在后台统一拉取消费明细，可由 WEB 端批量导入；存在的问题是无法获取每次充电后的里程数据

2. 若 OCR 技术不可行，则按照先拍照，再正常填写表单的流程执行。

### 5.5 上报记录

- 以卡片的形式展示当前用户权限范围内的填报记录，默认按照填报时间倒序排列，滚动显示，可上拉加载更多
- 支持按照项目、上报记录类型、上报时间等条件对记录进行筛选，默认为当前用户所属权限范围内的所有上报记录
	- 项目：默认为最近一次使用的项目
	- 上报记录类型：默认为全部，可选择加油、加水、充电
	- 上报时间：默认为近 7 天，支持自主选择时间范围
- 卡片内容包括：
	- 费用类型 - 车牌号 - 金额
	- 上报时间 - 上报人 - 项目
- 点击卡片后，能够进入对应记录详情查看页面
- 详情页面支持对记录的编辑，其中车牌号、车架号、所属项目字段不可编辑。编辑的字段均需记录，并在 WEB 端的变更记录中显示
- 支持删除己上报记录，删除前需要二次确认，点击后提示 " 确定删除该信息吗？删除后数据不可恢复。"，用户点击 " 确定 " → 执行逻辑删除 + 列表刷新；用户点击 " 取消 " → 关闭确认弹窗，不执行删除；删除权限为该条记录的上报用户、项目经理或管理员

| 状态   | 界面                      | 用户可执行操作                  |
| ---- | ----------------------- | ------------------------ |
| 未上传  | 显示拍照入口，信息区为初始页面         | 可跳过拍照直接手动填写，提交前需校验必填规则   |
| 识别中  | 照片下方显示“正在识别中”提示         | 提交按钮禁用，可以填写字段            |
| 识别成功 | 对应字段自动填充，标记“已识别”        | 重新拍照、修改、填写、提交；提交前需校验必填规则 |
| 识别失败 | 照片下方显示“识别失败，请重新上传或手动填写” | 重新拍照、填写；提交前需校验必填规则       |
| 部分识别 | 已识别字段自动填充，未识别的字段不填充     | 修改、填写、提交；提交前需校验必填规则      |

#### 5.6.2 字段标识状态

初始状态下，字段后不显示图标

字段识别成功，字段后显示成功图标

字段识别失败，字段后显示失败图标

字段识别后，用户手动修改，字段后不显示图标

#### 5.6.3 OCR 异常流程

1. 网络异常/弱网：OCR 请求超时或失败，提示 " 网络异常，OCR 识别失败，已为您切换至手动填写 "
2. OCR 整体识别结果置信度过低：按识别失败处理，照片下方显示 " 识别失败，请重新上传或手动填写 "，信息区对应字段保持为空
3. OCR 识别部分字段：照片下方显示“已识别字段填充并标记 " 已识别 "，未识别字段提示 " 未识别，请手动填写 "
4. 识别过程中用户填写了字段：OCR 结果仅覆盖对应字段的空值，不覆盖用户已手动填写的内容
5. 用户重新上传照片： 以最新识别结果覆盖对应字段，但用户已手动修改且识别结果未变的字段可保留
6.  用户删除已识别照片：不影响已填充和填写的字段

| 项目名称 | 下拉单选    |            |

**列表字段：**

- 复选框
- 所属项目
- 车牌号
- 车架号
- 油卡号
- 加油时间
- 加油单价（元/L）
- 加油量（L）
- 加油金额（元）
- 当前里程数（km）
- 里程照片：显示小缩略图，如无，显示 -，点击可查看具体照片
- 交易凭证：显示小缩略图，如无，显示 -，点击可查看具体照片

	- 删除：点击后提示 " 确定删除该信息吗？删除后数据不可恢复。"，用户点击 " 确定 " → 执行逻辑删除 + 列表刷新；用户点击 " 取消 " → 关闭确认弹窗，不执行删除
	- 变更记录：点击后打开变更记录弹窗，弹窗中有变更记录列表，列表字段依次为：字段名称、变更前、变更后、变更时间、变更人，按照变更时间倒序排列。首次新增时不作为变更

**操作按钮**

- **新增记录：** 点击后打开新增加油记录弹窗，弹窗字段信息同 APP 中加油记录上报页面，其中里程照片和交易凭证、支付照片均支持从设备本地上传

	- 导入时需要对文件进行合规校验
	- 如果存在校验失败的记录，则 toast 提示失败原因 + 对应行数，该批数据不做导入
- **导出：** 若用户有选中记录，导出用户选择的数据，不支持跨页选择导出；若用户未选中数据，提示：" 是否导出所有数据？"，用户选择 " 是 " 则导出当前筛选条件下的所有数据
