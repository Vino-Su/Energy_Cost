## 1. 业务背景与使用角色
### 1.1 业务背景
- 模块定位：为品质巡查人员在地图与服务浏览场景中提供统一、低路径的事件上报入口。
- 核心特点：快捷入口不改变当前地图或服务浏览状态，用户确认具体操作后再进入目标业务页面。
- 关联模块关系：快捷操作复用既有事件上报页面，由事件上报页面承接信息填写与提交校验。
### 1.2 使用角色

| 角色 | 该模块中的职责 | 客户端 |
| ---- | ------------ | ------ |
| 品质巡查员 | 打开快捷操作并进入事件上报 | 移动端 APP |

### 1.3 核心目标与价值

| 目标维度 | 说明 |
| -------- | ---- |
| 操作效率 | 缩短地图与服务场景进入事件上报的路径。 |
| 操作一致性 | 使用同一入口和同一操作集合承载跨页面快捷操作。 |

## 3. 功能详细设计
### 3.1 F01 快捷事件上报
#### 3.1.1 功能目标与范围

| 项目 | 说明 |
| ---- | ---- |
| 功能目标 | 使巡查员可从地图或服务浏览场景快速进入事件上报，并保持原有地图与服务导航结果不变。 |
| 使用角色 | 品质巡查员。 |
| 触发条件 | 巡查员在品质巡查应用主导航触发快捷入口。 |
| 功能边界 | 本期仅提供事件上报；不包含任务选择、事件表单填写、事件提交和事件处置。 |
| 成功结果 | 系统打开事件上报页面，并将事件关联至预设任务。 |

#### 3.1.2 使用条件与权限

| 角色 | 可执行操作 | 数据范围 | 前置条件 |
| ---- | ---------- | -------- | -------- |
| 品质巡查员 | 打开快捷操作、进入事件上报 | 预设任务 I002 的事件上报场景 | 已进入品质巡查应用。 |

#### 3.1.3 数据与字段规则

| 字段/条件 | 业务含义 | 取值方式或数据来源 | 默认值 | 校验/匹配规则 |
| --------- | -------- | -------------------- | ------ | ------------- |
| 快捷操作项 | 本期可从快捷入口进入的业务操作 | 系统配置 | 事件上报 | 本期仅保留事件上报。 |
| 关联任务 | 事件上报的任务上下文 | 系统预设 | I002 | 进入事件上报时固定传入 I002。 |
| 拍摄状态 | 事件上报页的进入状态 | 系统预设 | 已采集状态 | 进入事件上报时传入 captured=1。 |

#### 3.1.4 业务规则与状态变化

| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| -------- | -------- | -------- | ------------- |
| F01-R1 | 点击快捷入口 | 系统打开快捷操作集合，不切换地图或服务浏览状态，也不改变原有地图与服务入口的导航结果。 | 当前浏览状态不变。 |
| F01-R2 | 点击事件上报 | 系统直接打开事件上报页面，关联任务固定为 I002，进入状态为 captured=1。 | 页面上下文切换至事件上报。 |
| F01-R3 | 关闭快捷操作 | 系统关闭快捷操作集合。 | 当前浏览状态不变。 |

#### 3.1.5 交互流程
1. 巡查员在地图或服务浏览场景触发快捷入口。
2. 系统展示本期可用的快捷操作集合。
3. 巡查员选择“事件上报”。
4. 系统打开事件上报页面，携带任务 I002 和 captured=1。
5. 巡查员可继续在事件上报页面完成后续填写、提交或返回操作。
#### 3.1.7 外部依赖

| 依赖模块/服务 | 输入 | 输出 | 调用时机 | 失败处理 |
| ----------- | ---- | ---- | -------- | -------- |
| 事件上报页面 | 任务 I002、captured=1 | 事件上报页面 | 巡查员选择事件上报时 | 由事件上报页面处理页面加载与表单校验。 |
