## 1. 业务背景与使用角色
### 1.1 业务背景
- 模块定位：为品质巡查人员在地图与服务浏览场景中提供统一、低路径的事件上报入口。
- 入口关联：工作台城市管家入口选择或恢复巡查员后，复用原品质巡查全部功能；本文中的品质巡查应用指城市管家巡查员工作空间。角色切换直接进入目标角色地图首页，不增加任务进行中切换提示；后续功能与角色关联见《城市管家多角色地图演示PRD》。
- 核心特点：快捷入口不改变当前地图或服务浏览状态，用户确认具体操作后再进入目标业务页面。
- 关联模块关系：快捷操作复用既有事件上报页面，由事件上报页面承接信息填写与提交校验。
### 1.2 使用角色

| 角色 | 该模块中的职责 | 客户端 |
| ---- | ------------ | ------ |
| 品质巡查员 | 打开快捷操作并进入事件上报 | 移动端 APP |

### 1.3 核心目标与价值

| 目标维度 | 说明 |
| -------- | ---- |
| 操作效率 | 缩短地图与服务场景进入事件上报的路径。 |
| 操作一致性 | 使用同一入口和同一操作集合承载跨页面快捷操作。 |

## 3. 功能详细设计
### 3.1 F01 快捷事件上报
#### 3.1.1 功能目标与范围

| 项目 | 说明 |
| ---- | ---- |
| 功能目标 | 使巡查员可从地图或服务浏览场景快速进入事件上报，并保持原有地图与服务导航结果不变。 |
| 使用角色 | 品质巡查员。 |
| 触发条件 | 当前角色为巡查员，用户在城市管家巡查员工作空间主导航触发快捷入口。 |
| 功能边界 | 本期仅提供事件上报；不包含任务选择、事件表单填写、事件提交和事件处置。 |
| 成功结果 | 系统打开事件上报页面，并将事件关联至预设任务。 |

#### 3.1.2 使用条件与权限

| 角色 | 可执行操作 | 数据范围 | 前置条件 |
| ---- | ---------- | -------- | -------- |
| 品质巡查员 | 打开快捷操作、进入事件上报 | 预设任务 I002 的事件上报场景 | 已进入品质巡查应用。 |

#### 3.1.3 数据与字段规则

| 字段/条件 | 业务含义 | 取值方式或数据来源 | 默认值 | 校验/匹配规则 |
| --------- | -------- | -------------------- | ------ | ------------- |
| 快捷操作项 | 本期可从快捷入口进入的业务操作 | 系统配置 | 事件上报 | 本期仅保留事件上报。 |
| 关联任务 | 事件上报的任务上下文 | 系统预设 | I002 | 进入事件上报时固定传入 I002。 |
| 拍摄状态 | 事件上报页的进入状态 | 系统预设 | 已采集状态 | 进入事件上报时传入 captured=1。 |

#### 3.1.4 业务规则与状态变化

| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| -------- | -------- | -------- | ------------- |
| F01-R1 | 点击快捷入口 | 系统打开快捷操作集合，不切换地图或服务浏览状态，也不改变原有地图与服务入口的导航结果。 | 当前浏览状态不变。 |
| F01-R2 | 点击事件上报 | 系统直接打开事件上报页面，关联任务固定为 I002，进入状态为 captured=1。 | 页面上下文切换至事件上报。 |
| F01-R3 | 关闭快捷操作 | 系统关闭快捷操作集合。 | 当前浏览状态不变。 |

#### 3.1.5 交互流程
1. 巡查员在地图或服务浏览场景触发快捷入口。
2. 系统展示本期可用的快捷操作集合。
3. 巡查员选择“事件上报”。
4. 系统打开事件上报页面，携带任务 I002 和 captured=1。
5. 巡查员可继续在事件上报页面完成后续填写、提交或返回操作。
#### 3.1.7 外部依赖

| 依赖模块/服务 | 输入 | 输出 | 调用时机 | 失败处理 |
| ----------- | ---- | ---- | -------- | -------- |
| 事件上报页面 | 任务 I002、captured=1 | 事件上报页面 | 巡查员选择事件上报时 | 由事件上报页面处理页面加载与表单校验。 |

### 3.2 F02 事件上报信息填写
#### 3.2.1 功能目标与范围

| 项目 | 说明 |
| ---- | ---- |
| 功能目标 | 使巡查员在事件上报时按业务分类标注问题类型，提升事件分类准确度与后续处置分流效率。 |
| 使用角色 | 品质巡查员。 |
| 触发条件 | 巡查员进入事件上报页面，在“事件内容”章节填写事件信息。 |
| 功能边界 | 仅新增问题类型字段的填写、回显与清除；不改变事件图片必填校验、事件描述与语音输入、备注及提交结果。 |
| 成功结果 | 巡查员选定问题类型后，所选值作为该事件的问题类型；未选择时以系统识别结果为准。 |

#### 3.2.2 使用条件与权限

| 角色 | 可执行操作 | 数据范围 | 前置条件 |
| ---- | ---------- | -------- | -------- |
| 品质巡查员 | 选择、修改、清除问题类型 | 当前上报事件所属任务上下文 | 已进入事件上报页面。 |

#### 3.2.3 数据与字段规则

| 字段/条件 | 业务含义 | 取值方式或数据来源 | 默认值 | 校验/匹配规则 |
| --------- | -------- | ------------------ | ------ | ------------- |
| 问题类型 | 事件的问题分类，位于事件内容章节首位 | 巡查员按两级分类选择 | 空 | 选填；一级与二级均选定后才记为已选。 |
| 一级分类 | 问题类型的大类 | 业务字典 | 空 | 枚举值：环境卫生、市容秩序、设施设备、道路病害。 |
| 二级分类 | 一级分类下的具体问题 | 业务字典，随一级分类联动 | 空 | 枚举值：环境卫生（明显垃圾、垃圾渣土、果皮箱溢满、油污遗撒、大件垃圾）；市容秩序（车辆违停、乱堆物料、违规广告）；设施设备（环卫设施破损、公厕设施故障）；道路病害（路面破损、雨水口堵塞、路面淤积）。 |

#### 3.2.4 业务规则与状态变化

| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| -------- | -------- | -------- | ------------- |
| F02-R1 | 打开问题类型选择 | 系统按两级分类展示可选问题，默认定位到已选一级分类；未选择时定位到第一个一级分类。 | 无数据变化。 |
| F02-R2 | 选择一级分类 | 二级分类随一级分类联动刷新。 | 仅切换可选范围，不改变已选值。 |
| F02-R3 | 选择二级分类 | 系统记录所选一级与二级分类，并关闭选择面板。 | 问题类型记为「一级分类 / 二级分类」。 |
| F02-R4 | 重新打开选择 | 系统回显当前已选一级与二级分类。 | 无数据变化。 |
| F02-R5 | 清除选择 | 系统清空已选问题类型，回到未选择状态；未选择时不可执行清除。 | 问题类型恢复为空。 |
| F02-R6 | 清空事件内容 | 清空事件内容时同步清空问题类型。 | 问题类型恢复为空。 |
| F02-R7 | 提交事件 | 问题类型为选填，未选择不阻断提交；提交后所选问题类型作为该事件的问题类型。 | 事件问题类型以巡查员所选值为准；未选择时沿用系统识别结果。 |

#### 3.2.5 交互流程
1. 巡查员进入事件上报页面，事件内容章节首位展示问题类型，初始为未选择。
2. 巡查员打开问题类型选择，系统按一级分类与二级分类展示可选问题，默认展开的一级分类为已选一级分类，未选择时展开第一个一级分类。
3. 巡查员选择一级分类，二级分类联动刷新。
4. 巡查员选择二级分类，系统回填「一级分类 / 二级分类」并关闭选择面板。
5. 巡查员可重新打开修改或清除选择；未选择或已清除时，提交事件仍可继续，问题类型不参与校验。

#### 3.2.6 异常处理

| 异常场景 | 触发条件 | 处理方式 |
| -------- | -------- | -------- |
| 未选择即提交 | 巡查员未选择问题类型直接提交 | 不阻断提交，事件问题类型沿用系统识别结果。 |
| 仅选定一级 | 巡查员选定一级分类后直接关闭选择面板 | 视为未选择，需一级与二级均选定后才记为已选。 |
| 重复点击同一选项 | 巡查员连续点击同一二级分类 | 幂等处理，问题类型保持为最后选中的值。 |
