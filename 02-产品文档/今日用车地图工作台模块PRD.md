## 2 名词解释

| 名词/缩写 | 解释                                      |
| ----- | --------------------------------------- |
| 今日用车  | 司机在城市管家 APP 中开始当天车辆使用与任务执行的主入口          |
| 地图工作台 | 以地图为主体承载待办任务、导航路线、实时轨迹、异常提醒和辅助操作的司机工作界面 |
| 人车绑定  | 驾驶员与车辆在一定时间范围内建立的使用关系，是进入今日用车主流程的前置状态   |
| 接车    | 驾驶员开始使用车辆时，通过扫码等绑定动作建立人车绑定关系            |
| 交车    | 驾驶员结束使用车辆时，通过交车确认解除人车绑定关系               |
| 动态任务  | 作业过程中由系统识别、调度或异常事件触发并临时推送给司机处理的任务       |
| 阻断项   | 未处理前不允许继续执行关键动作的事项，如未结束任务、车辆不可用         |
| 提醒项   | 需要提示司机关注但不强制阻断当前动作的事项，如异常待确认、照片待补充      |

## 3 业务背景与使用角色
### 3.1 业务背景
- 模块定位：今日用车地图工作台是车辆使用过程监管方案在司机端 APP 的主流程承载模块，用于把接车状态、任务执行、轨迹导航、动态任务、异常提醒、水电油上报、故障报修、结束任务和交车收口串联到一个以地图为核心的工作界面。
- 核心特点：司机打开 APP 后进入“今日用车”，系统先校验司机是否已绑定车辆；已绑定则直接进入地图工作台，未绑定则展示未绑定提示并引导完成车辆绑定；本期不建设单独司机展示二维码页面或入口。
- 业务痛点：原车辆使用动作分散在多个功能中，司机需要自行查找任务、报修、补给等入口；管理侧难以稳定追踪人车关系、任务路线、轨迹偏差、异常响应和交车闭环。
- 关联模块关系：模块从 basis 平台读取车辆信息，从环卫云平台读取常规任务、动态任务、轨迹和异常记录，从售后平台同步维修工单，从能耗成本模块复用水电油上报能力。
### 3.2 使用角色

| 角色       | 该模块中的职责                                                                | 客户端       |
| -------- | ---------------------------------------------------------------------- | --------- |
| 作业车辆驾驶员  | 进入今日用车、完成绑定状态校验、查看地图工作台、查看任务、调用外部地图导航、开始/结束任务、处理动态任务、上报水电油、发起故障报修、完成交车 | 移动端 APP   |
| 项目经理/管理员 | 查看异常记录、核查车辆使用异常、处理合规异常、调整任务或维修资源                                       | 管理端/环卫云平台 |
| 系统服务     | 判断绑定状态、同步车辆可用性、聚合任务待办、接收轨迹数据、生成异常记录、保存接车/交车留痕                          | 后端服务      |

### 3.3 核心目标与价值

| 目标维度   | 说明                                 |
| ------ | ---------------------------------- |
| 司机操作效率 | 将司机高频工作收敛到地图工作台，减少多入口跳转和学习成本       |
| 主流程清晰  | 形成“今日用车校验 - 地图任务 - 结束任务 - 交车”的稳定路径 |
| 监管留痕   | 自动沉淀人员、车辆、时间、位置、轨迹、异常、上报和交车记录      |
| 风险控制   | 对未绑定车辆、车辆不可用、未结束任务、阻断项等关键场景进行提示或拦截 |
| 业务融合   | 将水电油上报和故障报修作为工作台辅助动作，支持任务执行期间穿插处理  |

## 5 功能详细设计
### 5.1 F01 今日用车卡片

#### 5.1.3 前置校验

| 校验条件             | 提示信息             | 阻断操作       |
| ---------------- | ---------------- | ---------- |
| 当前司机已绑定有效车辆      | 无需提示             | 允许进入地图工作台  |
| 当前司机未绑定车辆        | 暂未绑定车辆，请先完成车辆绑定  | 不允许进入地图工作台 |
| 当前绑定关系已失效        | 绑定状态已失效，请重新绑定车辆  | 不允许进入地图工作台 |
| 当前绑定车辆被标记为维修中    | 当前车辆维修中，暂不可用车    | 不允许进入地图工作台 |
| 当前绑定车辆证照/保险/年检到期 | 车辆不满足用车条件，请联系管理员 | 不允许进入地图工作台 |
| 当前司机账号无今日用车权限    | 暂无今日用车权限         | 不允许进入地图工作台 |

#### 5.1.4 交互流程
1. 司机打开 APP，进入用车管理工作台。
2. 系统查询司机当前人车绑定状态，并显示在 “今日用车”卡片上
	- 如果已绑定车辆，卡片右侧显示绑定的车辆牌照
	- 如果未绑定车辆，卡片右侧显示：“当前未绑定车辆”
3. 司机点击“今日用车”卡片，系统查询司机当前人车绑定状态和车辆可用状态：
	- 已绑定且车辆可用 → Toast 提示“进入今日用车”，跳转地图工作台。
	- 未绑定车辆 → 展示未绑定引导弹窗，不进入地图工作台。
	- 已绑定但车辆不可用 → 展示不可用原因，不进入地图工作台。
4. 未绑定引导弹窗展示内容：
	- 提示文字
	- 去绑定车辆：唤起既有绑定/扫码能力 → 绑定完成后重新校验并进入地图工作台。
	- 关闭：点击后关闭引导页。
#### 5.1.5 弹窗规格

| 属性 | 值 |
| ---- | -- |
| 弹窗名称 | 车辆不可用提示弹窗 |
| 触发入口 | 点击今日用车后校验失败 |
| 位置 | 居中弹出或页面内提示，移动端按设计规范选用 |
| 标题 | 无法进入今日用车 |
| 内容 | 车辆不可用或绑定异常的具体原因 |
| 主按钮 | 知道了 |
| 次按钮 | 联系管理员/返回首页，按项目配置展示 |

### 5.2 F02 地图工作台
#### 5.2.1 页面布局

地图工作台为司机已绑定车辆后的主页面，页面自上而下/由外到内分为 6 个区域：

1. **地图主体区**：全屏或近全屏展示地图，显示车辆当前位置、任务路线、实时轨迹、目标点、异常点和动态任务点；高保真原型采用内置 SVG/CSS 仿地图底图承载路线与车辆移动，真实开发可按地图供应商能力替换底图层。
2. **顶部状态栏**：以车辆执行状态条呈现，展示返回入口、车牌号主信息、车型/今日任务副信息、车辆状态。
3. **右侧悬浮工具组**：提供定位回正、图层切换、异常提醒、水电油上报、故障报修、交车等快捷操作。
4. **底部待办任务抽屉**：默认半展开，展示当前任务、待办任务和任务状态；上滑展开完整待办列表。
5. **任务执行状态条**：执行中展示任务进度、已作业时长、路线覆盖提示和结束任务按钮。
6. **消息提醒层**：用于展示动态任务推送、异常播报、强提醒和轻提示；行驶中系统派发的新任务以地图上方 banner 轻提醒呈现，宽度与顶部车牌信息卡一致，信息靠左排列，右侧固定“查看”按钮，内容格式为“新动态任务 任务名称 - 距离 查看”，点击后聚焦对应待办任务。

#### 5.2.4 交互流程

**当日有待办任务**

1. 进入地图工作台后，此时还未开始任务，底部显示任务卡片，默认显示该车辆 + 该司机时间排序在第一位的任务，当前车辆地图中默认显示当前车辆位置 + 该任务计划路线，任务卡片支持拉起显示全部今日待办任务（可覆盖地图，也支持收起），也可以通过点击右侧“展开任务”达到相同的效果。清单中执行中任务优先，其次依次展示应急任务、动态任务、常规任务；已完成任务统一移动至列表底部。
	- 存在执行中任务 → 默认选中执行中任务。
	- 存在动态任务 → 动态任务优先展示，排在执行者任务后。
	- 仅存在常规任务、应急任务 → 按计划开始时间排序展示。
	- 无待办任务 → 展示空任务状态和交车引导。
2.  驾驶员选中某任务时，地图上显示该任务计划路线信息，卡片变为该任务的详细信息，有以下按钮：
	- 导航按钮：以小图标按钮呈现，点击后调用高德地图 API 进行外部导航；
	- 开始任务：点击后进入需要校验是否满足开始任务条件。满足条件后，进入任务执行
		- 校验车辆的位置是否在路段范围：若不通过，toast 提示“当前车辆距离任务路段过远”
		- 是否有其他正在执行的任务：若不通过，toast 提示“请先结束当前任务”，任务卡片跳转为正在执行中的任务
	- 任务详情：次按钮，查看详细要求，不作为主操作
	- 更多按钮：点击后显示暂停任务、关闭任务按钮
		- 暂停任务：将当前正在执行中的任务暂停，在此状态下，用户可以开始执行其他任务
		- 关闭任务：将选中的任务予以关闭
3. 任务执行状态下，地图上显示任务的计划路线信息（蓝色虚线）和车辆的实际移动轨迹（红色实线）。车辆位置点实时刷新，并更新作业里程、已作业时长。底部卡片显示执行中的任务信息（作业路段、计划时间、作业要求、已作业时间、作业里程），有以下按钮：
	- 结束任务：主按钮，点击后进行未完成事项校验，通过后结束任务，未通过则无法结束
	- 任务详情
	- 导航
4. 司机收到新任务提醒：
   - 轻提醒 → 地图上方 banner 提示，宽度与顶部车牌信息卡一致，信息靠左排列，右侧固定“查看”按钮；
   - 内容格式为“新动态任务 任务名称 - 距离 查看”，支持快捷跳转并查看动态任务
   动态任务同步进入底部待办任务列表，任务卡片支持导航、开始任务、结束任务
5. 司机点击辅助按钮 → 打开水电油上报类型选择器、故障报修弹窗或交车检查弹窗
### 5.3 F03 任务详情与执行抽屉
#### 5.3.1 页面布局

任务详情与执行抽屉承载在地图底部，按任务状态展示不同内容：

1. **收起态**：展示任务名称、时间、状态和主按钮。
2. **半展开态**：展示任务路线、作业要求、导航按钮和任务操作。
3. **全展开态**：点击“展开任务”后展示完整任务列表，触发按钮文案切换为“收起任务”，支持切换任务；展开后地图车辆图标层级低于任务面板，不得浮在面板上方。
4. **执行态**：展示执行进度、实际轨迹、路线覆盖提示、异常提醒和结束任务按钮。
#### 5.3.2 数据列表区

| 序号 | 任务类型 | 左侧第一行 | 左侧第二行 | 最右侧 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 常规任务 | 路线名称 + 任务类型 | 路段 + 作业时间 | 任务状态 | 任务类型使用独立标签；状态枚举值：待开始、执行中、已完成、异常关闭 |
| 2 | 应急任务 | 路线名称 + 任务类型 | 路段 + 作业时间 | 任务状态 | 应急任务类型使用错误色浅底标签，但不得替代任务状态 |
| 3 | 动态任务 | 问题类型 + 问题重要程度 + 任务类型 | 问题地点 | 任务状态 | 动态任务类型使用警告色浅底标签；问题地点超长时单行省略 |

**排序规则：**

1. 已完成任务统一排列在所有未完成任务之后；多条已完成任务保持原业务顺序。
2. 未完成任务中，执行中任务优先，其次依次为应急任务、动态任务、常规任务。
3. 同类型待开始任务按计划开始时间升序；无明确计划时间的任务保持原业务顺序。
4. 动态任务派发进入清单、任务开始或结束后，立即按上述规则重新排序。

#### 5.3.3 前置校验

| 校验条件 | 提示信息 | 阻断操作 |
| -------- | -------- | -------- |

| 开始任务时不在计划时间窗口 | 当前不在计划任务时间内，请确认后再开始 | 按项目规则提醒或阻断 |
| 存在执行中任务时开始另一任务 | 请先结束当前任务 | 阻断新任务开始 |

#### 5.3.4 交互流程
1. 司机在底部抽屉点击“展开任务”查看今日任务列表；列表展开后按钮文案变为“收起任务”，再次点击或点击列表内“收起任务”可收起列表。每张任务卡片按任务类型展示差异化字段，任务类型显示在左侧内容区，任务状态统一固定在卡片最右侧。
2. 司机点击任务卡片 → 地图显示该任务路线、起终点和当前位置。
3. 任务卡片内展示导航图标按钮；司机点击后调用高德地图导航 API，跳转外部地图导航至任务路段，不在 APP 内承载导航过程。
4. 当被查看任务处于未开始状态时，底部当前任务卡片下方展示“开始任务”主按钮；任务详情按钮弱化为次要文字/小按钮。
5. 司机点击”开始任务”：
   - 校验成功 → 任务状态变为”执行中”，开始采集实际轨迹；若开始前任务列表处于展开状态，则自动收起列表，仅展示当前执行任务（聚焦作业注意力，避免多任务视觉干扰）。
   - 校验失败 → 展示定位或时间校验原因。
6. 执行中系统持续展示实际轨迹和异常提醒。
7. 用户点击“任务详情”，打开对应任务详情页面
8. 司机完成作业后点击“结束任务”：
   - 校验通过 → 当前任务状态变为“已完成”，记录作业里程、时间校验和异常信息。
   - 存在阻断项 → 提示具体阻断原因，任务保持执行中。
8. 当前任务结束后，系统自动检查下一条待办任务：
   - 存在下一任务 → 自动选中并推送下一任务卡片，展示“开始任务”按钮。
   - 无下一任务 → 展示返场交车提示。

#### 5.5.3 前置校验

| 校验条件      | 提示信息      | 阻断操作 |

| 故障影响未选择   | 请选择故障影响程度 | 阻断提交 |
| 故障描述为空或过短 | 请补充故障描述   | 阻断提交 |

#### 5.5.4 交互流程
1. 司机点击“故障报修”。
2. 系统打开报修弹窗并带入当前车辆和位置。
3. 司机选择故障影响程度并填写信息。
4. 司机点击“提交报修”：
   - 校验成功 → 创建维修工单并推送售后平台，Toast 提示“报修已提交”。
   - 校验失败 → 展示字段错误，弹窗不关闭。
5. 若故障影响为“影响作业且无法自行返回” → 系统提示作业终止并引导等待维修。
6. 若故障影响为“影响作业但可自行返回” → 系统提示导航至维修场地。
7. 若故障影响为“不影响作业” → 系统允许继续当前任务。
### 5.6 F06 结束任务校验与推送
#### 5.6.1 页面布局

结束任务能力承载在地图工作台的执行中任务卡片内，不单独跳转结束任务确认页：

1. **执行任务卡片**：展示任务名称、计划时间、实际开始时间、已执行时长、作业里程和异常摘要。
2. **结束任务按钮**：执行中任务展示主按钮“结束任务”。
3. **校验反馈区**：点击结束任务后，以 Toast、轻提示或卡片内提示展示校验结果。
4. **下一任务推送区**：结束成功后自动选中下一条待办任务；无下一任务时展示返场交车提示。

#### 5.6.3 前置校验

| 校验条件 | 提示信息 | 阻断操作 |
| -------- | -------- | -------- |
| 当前无执行中任务 | 当前无可结束任务 | 阻断结束 |

#### 5.6.4 交互流程
1. 司机在执行中任务卡片点击“结束任务”。
2. 系统校验作业里程、时间完成情况、动态任务闭环状态和阻断项：
   - 校验成功 → 任务状态变为“已完成”，Toast 提示“任务已结束”。
   - 存在提醒项 → 记录提醒项，允许结束任务。

3. 系统检查是否存在下一待办任务：

#### 5.7.4 交互流程

1. 点击交车按钮，系统先进行校验，看是否存在未完成任务

	- 明日待办：以卡片形式展示明日的任务；如无，则显示暂无明日待办任务；V1.5 起每条任务支持点击查看详情（见 5.7.8）

##### 5.7.6.3 未完成状态枚举与排序

| 状态枚举 | 中文标签 | 颜色规范 | 排序优先级 |
| -------- | -------- | -------- | ---------- |
| pending | 待开始 | 浅蓝 #e6f4ff / 主色 #1677ff | 2 |
| running | 执行中 | 浅绿 #f6ffed / 成功 #52c41a | 1（最高） |
| abnormal | 异常关闭 | 浅红 #fff1f0 / 错误 #ff4d4f | 3（最低） |

**排序规则：**

1. 分组内任务按"执行中 → 待开始 → 异常关闭"优先级排序；
2. 同状态任务按计划开始时间升序排列；
3. 计划开始时间为空的任务保持原业务顺序。

## 7 业务规则汇总
### 7.1 今日用车入口分流规则

| 当前状态         | 系统行为             |
| ------------ | ---------------- |
| 司机已绑定车辆且车辆可用 | 进入地图工作台          |
| 司机未绑定车辆      | 展示未绑定引导，不进入地图工作台 |
| 绑定关系失效       | 提示重新绑定车辆         |
| 车辆不可用        | 展示不可用原因，不进入地图工作台 |

### 7.2 本期二维码能力边界

| 规则项 | 说明 |
| ------ | ---- |
| 独立司机二维码 | 本期不建设独立入口、独立页面或个人中心展示能力 |
| 未绑定引导 | 仅提示司机需要完成车辆绑定，并可跳转或唤起既有绑定/扫码能力 |
| 外部扫码能力 | 如车辆端扫码司机二维码由其他系统提供，本模块仅接收绑定结果并重新校验 |
| 页面验收 | 不验收司机展示二维码页面、动态码刷新、二维码有效期等能力 |

### 7.3 人车绑定与可用性规则

| 场景          | 规则                     |
| ----------- | ---------------------- |
| 无绑定车辆进入今日用车 | 阻断进入地图工作台，提示先绑定        |
| 已绑定车辆进入今日用车 | 查询车辆可用状态，可用则进入地图工作台    |
| 车辆已被他人绑定    | 不允许当前司机使用              |
| 当前司机已绑定其他车辆 | 不允许自动换车，需先完成原车辆交车      |
| 车辆故障未修复或维修中 | 不允许进入今日用车主流程           |
| 年检/保险/牌照到期  | 按车辆不可用处理，接车或进入今日用车时强拦截 |

### 7.4 状态流转规则

```text
未绑定
  -> 今日用车校验
      -> 未绑定：展示引导
      -> 已绑定且可用：进入地图工作台
地图工作台
  -> 查看任务
  -> 可选调用高德地图导航
  -> 开始任务
  -> 执行任务
      -> 动态任务/异常提醒/水电油上报/故障报修
  -> 结束任务
      -> 有下一任务：推送下一任务
      -> 无下一任务：引导返场交车
  -> 交车（前置校验）
      -> 存在进行中未结束任务：toast 提示 + 高亮待办，不可交车
      -> 仅未开始任务或无未完成任务：进入二维码交车 -> 扫码成功解除绑定 -> 今日回顾+明日待办页
```

### 7.5 任务执行规则

| 规则项 | 说明 |
| ------ | ---- |
| 任务优先级 | 执行中任务优先，其次应急任务，其次常规任务 |
| 任务查看 | 司机点击任务卡片后，地图切换至该任务路线，卡片展示开始任务、导航图标和弱化任务详情入口 |
| 外部导航 | 司机点击导航图标后调用高德地图 API，不在 APP 内承载导航过程 |
| 开始任务 | 需校验车辆位置是否在任务路段范围，计划时间校验按项目配置 |
| 执行任务 | 实时上传位置、速度、轨迹等数据至环卫云平台；原型中当前执行任务使用约 25 个计划路线点和 26 个实际轨迹点表现较长、曲折路线，实际轨迹可与计划路线存在轻微偏离，演示动效按 1.8 秒/点推进 |
| 结束任务 | 在地图工作台内校验作业里程、时间完成情况和动态任务闭环状态，校验通过后直接结束 |
| 任务推送 | 上一任务结束后自动检查并推送下一任务 |

### 7.6 动态任务规则

| 规则项 | 说明 |
| ------ | ---- |
| 触发来源 | 摄像头识别、调度派发、异常事件等 |
| 展示方式 | 地图上方 banner 轻提醒、地图高亮点位、底部任务抽屉置顶、语音播报；原型示例包含 1 条行驶中派发的动态任务 |
| 与主线关系 | 可作为常规任务中的插曲，处理后回到原常规任务 |
| 闭环机制 | 按“开始 - 执行 - 结束”处理，是否必须闭环见待确认项 |

### 7.7 异常监控规则

| 异常大类 | 异常事件 | 司机端处理 | 管理端处理 |
| -------- | -------- | ---------- | ---------- |
| 使用异常 | 车辆行驶未关联驾驶员 | 本模块在今日用车入口阻断未绑定使用 | 推送项目经理核查 |
| 使用异常 | 车辆长时间未交车 | 提醒交车 | 推送项目经理核查 |

| 未开始任务 | 是 | 不阻断交车 |
| 无未完成事项 | 是 | 解除人车绑定并生成今日回顾 |

### 人车关系校验规则
出现以下情况，视为车辆可用性校验失败，不建立司机与车辆的使用关系
- 当前车辆已与其他司机绑定
- 当前司机已与其他车辆绑定
也就是说同一时段内，一辆车只能与一个司机建立使用关系
