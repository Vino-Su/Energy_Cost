## 3 业务背景与使用角色

### 3.1 业务背景

- 模块定位：是 `01-需求文档/车务管理-能耗成本上报需求文档-融合OCR版本.md` §6 中描述的 WEB 端能耗记录汇集页，承担司机上报数据汇集、审单、改单、删除、批量导入导出和变更追溯的全流程治理。
- 当前痛点：①列表字段过多、缺乏汇总，每次审单都要先 Excel 导出才能看到合计；②照片缩略图铺满表格，关键证据淹没；③缺乏"项目"维度的快速切换，跨项目盘点需要反复修改筛选条件；④加油"油卡余额"、充电"电费/服务费"等明细字段缺失，影响后续成本结构对账。
- 改造重点：列瘦身、详情/编辑能力、筛选范围汇总、项目切换、表单新增字段，以及信息管理模块的统一入口和项目上下文。
- 上下游模块：从 `酷哇 APP` 移动端采集记录、在本模块审单改单、同步变更记录到变更审计、回流消耗数据到成本汇总。

### 3.2 使用角色

| 角色   | 该模块中的职责                | 客户端       | 数据权限                                  |
| ---- | ---------------------- | --------- | ------------------------------------- |
| 项目经理 | 跨项目盘点、审核、改单、导入导出      | WEB 端     | 本人关联的项目；负责的项目内所有的上报数据               |
| 车队长  | 协助项目经理日常审单、改单         | WEB 端     | 本人关联的项目；负责的项目内所有的上报数据               |
| 管理员  | 全量数据治理、纠错、批量导入导出、变更审计 | WEB 端     | 所有数据                                   |

> 注：`司机` 角色仅移动端 APP 可见，WEB 端不参与；详见 §6.1 需求文档中"项目经理"用户类型。

### 3.3 核心目标与价值

| 目标维度   | 说明                           |
| ------ | ---------------------------- |
| 列表扫读效率 | 列瘦身 + 关键证据缩略图，提升第一屏扫描效率     |
| 成本对账   | 当前筛选汇总，方便快速了解筛选范围内的记录数、数量与金额 |
| 多项目盘点   | 项目切换按钮一键切换上下文，无需反复设筛选       |
| 模块一致性   | 能耗记录使用信息管理统一入口、项目和用户上下文 |
| 数据完整性   | 新增"油卡余额""电费/服务费"字段，支持成本结构对账 |
| 详情编辑高效  | 在当前列表内完成详情查看和编辑，避免页面跳转并保持筛选上下文     |

## 5 功能详细设计

### 5.1 F01 列瘦身与列表重排

#### 5.1.1 查询与重排规则

| 类型 | 查询条件 | 查询规则 |
| ---- | ---- | ---- |
| 加油 | 加油时间、车牌号、关联油卡、上报人 | 时间精确到日且默认近半年；文本条件支持模糊搜索 |
| 加水 | 加水时间、车牌号、支付方式、上报人 | 支付方式枚举：全部、月付、现金、线上支付 |
| 充电 | 充电结束时间、车牌号、支付方式、上报人 | 支付方式枚举：全部、充电卡、现金、线上支付 |

| 类型       | 列表保留的列                                                                                                                                                                                                                                                          | 移到详情弹窗的字段                                 |
| -------- |---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------- |
| **加油**   | 复选框 / 车牌号 / 加油时间 / 加油量 (L) / 加油单价 (元/L) / 加油金额 (元) / 当前里程数 (km) / **交易凭证**（关键证据缩略图）/ 上报人 / 操作                                                                                                                       | 车架号、上报时间、备注、油卡号、支付方式、**里程照片**           |
| **加水**   | 复选框 / 车牌号 / 加水时间 / 加水量 (吨) / 支付方式 / 加水金额 (元) / 当前里程数 (km) / 上报人 / 操作                                                                                                                                                                            | 车架号、上报时间、备注、支付照片（上移至详情页 **展示完整**）、里程照片         |
| **充电**   | 复选框 / 车牌号 / 充电开始时间 / 支付方式 / 充电度数 (度) / 充电金额 (元) / 当前里程数 (km) / **充电截图明细**（关键证据缩略图）/ 上报人 / 操作                                                                                                                            | 车架号、上报时间、备注、**里程照片**、**支付照片**                |

> 共同特征：三个页面均**不展示"所属项目"**列，因项目已通过右上角下拉切换为强上下文。

#### 5.1.2 列表交互

- 表格行高严格 48px、内边距 16px（沿用 UI_design_WEB.md 规范）；
- 数字列右对齐并使用 `DIN` 字体（数量、金额、单价）；
- 文本/时间列左对齐；
- 时间、状态标签对齐方式居中（与表格规范一致）；
- 行尾"操作"列居中，包含：详情（link-button）+ 编辑（text-button）+ 更多 ▾（下拉）；
- 行 hover 高亮背景 #fafafa；
- 缩略图 40×40，圆角 4px，hover 放大 1.1× + 阴影；
- 选择计数显示在右上角："已选 N 条"。

#### 5.1.3 当前筛选汇总

| 类型 | 汇总指标 | 计算口径 |
| -- | -- | -- |
| 加油 | 记录数、加油量、加油金额 | 数量与金额分别按当前筛选结果求和 |
| 加水 | 记录数、加水量、加水金额 | 数量与金额分别按当前筛选结果求和 |
| 充电 | 记录数、充电度数、充电金额 | 数量与金额分别按当前筛选结果求和 |

> 汇总范围随项目和查询条件变化而重新计算；切换页码或每页条数不改变汇总值。

#### 5.1.4 列表样式规范

- 表格主区高度不强制固定，超过屏高启用整页内滚动；
- 表格右侧允许超宽时整体水平滚动（设计要求 §4 表格 `overflow-x: auto`）。

### 5.2 F02 / F03 详情与编辑弹窗

#### 5.2.1 功能范围

| 项目 | 规则 |
| ---- | ---- |
| 打开方式 | 用户在列表行点击详情或编辑后，在当前列表页打开弹窗，不发生页面跳转 |
| 数据绑定 | 弹窗按所选记录 ID 获取数据；记录不存在或已删除时提示“记录不存在或已删除” |
| 内容结构 | 仅显示字段名称与字段值，不展示摘要条、不设置基础信息、费用信息、照片证据等分组 |
| 上下文 | 弹窗打开期间保留当前项目、查询条件、页码和列表位置 |
| 关闭方式 | 支持关闭按钮、取消按钮、遮罩点击和 Esc 键关闭 |

#### 5.2.2 字段范围

| 类型 | 详情与编辑字段 |
| ---- | ---- |
| 加油 | 车牌号、车架号、所属项目、上报人、加油时间、加油单价、加油量、加油金额、支付方式、关联油卡、油卡余额、当前里程数、备注、里程照片、交易凭证 |
| 加水 | 车牌号、车架号、所属项目、上报人、加水时间、加水量、加水金额、支付方式、当前里程数、备注、里程照片、支付照片 |
| 充电 | 车牌号、车架号、所属项目、上报人、充电开始时间、充电结束时间、充电时长、充电度数、电费、服务费、充电金额、支付方式、当前里程数、备注、里程照片、充电明细截图、支付照片 |

#### 5.2.3 交互与保存规则

1. 详情弹窗展示当前记录的字段值，底部提供关闭、删除和编辑操作。
2. 点击编辑后在原弹窗位置切换为编辑态，并预填当前记录数据。
3. 车牌号、车架号、所属项目和充电时长不可编辑；其他字段按业务规则校验。
4. 保存成功后更新当前记录、关闭弹窗并按现有查询条件刷新列表；校验失败时弹窗保持打开并提示原因。
5. 详情弹窗内点击删除时关闭详情弹窗并打开原删除确认弹窗，确认后刷新列表。

### 5.3 F04 操作按钮收纳

| 操作   | 列表行尾落位                                                              | 详情弹窗落位            |
| ---- | ------------------------------------------------------------------ | ---------------- |

| 编辑   | 文本按钮                                                                | 主操作按钮（蓝色实心）       |

### 5.4 F05 当前筛选汇总

- 汇总数据范围与当前项目及各类型有效查询条件一致：加油按时间、车牌号、关联油卡、上报人；加水按时间、车牌号、支付方式、上报人；充电按结束时间、车牌号、支付方式、上报人；
- 切换页码或每页条数时，汇总数据保持不变；新增、删除、项目切换或重新查询后重新计算；
- 数量和金额按命中记录分别求和，不计算或展示综合单价、单位成本、加权均价等单价类衍生指标；
- 筛选结果为 0 条时保留范围说明，数量和金额显示"—"，避免与真实的零值混淆。

### 5.5 F06 项目切换按钮

#### 5.5.1 功能目标与范围
| 项目 | 说明 |
| ---- | ---- |
| 功能目标 | 以当前项目作为加油、加水、充电记录的统一数据范围 |
| 使用角色 | 项目经理、车队长、管理员 |
| 成功结果 | 当前列表、记录数量和新增记录归属项目保持一致 |

#### 5.5.2 项目数据范围
| 角色 | 可选项目 | 默认项目 |
| ---- | ---- | ---- |
| 项目经理/车队长 | 本人关联且具有查看权限的项目 | 上次成功选择的项目；无历史时使用关联项目中的默认项目 |
| 管理员 | 权限系统返回的全部可管理项目 | 上次成功选择的项目 |

#### 5.5.3 交互流程
1. 用户进入任一能耗记录列表，系统读取当前项目上下文。
2. 用户选择其他有权项目，系统更新当前项目并重新查询列表。
3. 系统清空切换前的勾选记录，保留项目选择以便用户切换到其他能耗类型时继续使用。
4. 用户新增记录时，系统自动带入当前项目且不允许修改。
5. 用户进入单条记录的详情或编辑过程后，系统锁定项目上下文；返回列表后恢复项目切换能力。

#### 5.5.4 异常处理
| 异常场景 | 系统处理 | 用户结果 |
| ---- | ---- | ---- |
| 项目权限被收回 | 停止加载该项目记录并切换到可用默认项目 | 提示原项目已无访问权限 |
| 项目数据加载失败 | 保留用户已输入的非项目筛选条件，不展示其他项目数据 | 提示加载失败并允许重试 |
| 无可用项目 | 不加载记录数据 | 提示联系管理员分配项目权限 |

### 5.7 F08 充电字段分解

#### 5.7.1 字段属性

| 字段        | 类型     | 必填 | 默认        | 备注                       |

#### 5.7.2 联动计算逻辑（用户最常问）

```
默认状态：
  onAmountChange('electric')  // 修改电费 / 服务费
     ↓
  if (!amountManual) {
     formAmount = electricFee + serviceFee;
     display  '自动计算（电费 + 服务费）'
  }

用户手写覆盖：
  onManualAmount()
     ↓
  amountManual = true;
  formAmount = userInput;
  display  '已手动调整，点击【重新联动】'
```

#### 5.7.3 校验规则

- 充电电费 ≥ 0、充电服务费 ≥ 0；
- 充电金额 ≥ 0；
- 充电金额自动联动的容差 ≤ 0.01 元（演示用：(电费 + 服务费).toFixed(2) === 金额）；
- 提交前若金额经手写但与电费+服务费差额 > 0.01，弹窗提示用户确认保留手动值（V1 不强制阻断）。

### 5.8 F09 信息管理模块集成

#### 5.8.1 功能目标与范围
| 项目 | 说明 |
| ---- | ---- |
| 功能目标 | 用户在信息管理模块内统一进入加油、加水、充电记录，并在三类记录之间保持连续的项目和用户上下文 |
| 使用角色 | 项目经理、车队长、管理员 |
| 功能范围 | 信息管理模块识别、能耗成本管理功能分组、三类记录入口、用户上下文、返回操作 |
| 功能边界 | 不改变实时管理、作业制定、数据分析和城市治理的业务逻辑 |
| 成功结果 | 三类记录的导航层级、项目范围和用户身份保持一致 |

#### 5.8.2 使用条件与权限
| 角色 | 可访问功能 | 数据范围 | 前置条件 |
| ---- | ---- | ---- | ---- |
| 项目经理/车队长 | 加油、加水、充电记录 | 本人有权项目的记录 | 已登录且至少具有一个项目权限 |
| 管理员 | 加油、加水、充电记录 | 权限系统授权的项目记录 | 已登录且具有能耗成本管理权限 |

#### 5.8.3 交互流程
1. 用户进入信息管理，系统识别当前登录用户和项目上下文。
2. 用户进入能耗成本管理中任一记录类型，系统加载对应列表。
3. 用户在加油、加水、充电记录之间切换时，系统保留当前项目上下文并切换当前功能识别。
4. 用户进入详情或编辑过程后，系统保持当前记录类型和项目上下文；返回时回到对应列表。

#### 5.8.4 异常处理
| 异常场景 | 系统处理 | 用户反馈 | 恢复方式 |
| ---- | ---- | ---- | ---- |
| 当前功能无权限 | 不加载能耗记录 | 提示无访问权限 | 返回有权功能或申请权限 |
| 用户或项目上下文加载失败 | 不展示其他用户或项目数据 | 提示上下文加载失败 | 允许重试或重新登录 |

## 6 异常流程与边界

| 场景                | 处理                                                                                |
| ----------------- | --------------------------------------------------------------------------------- |
| 列表筛选结果 0 条        | 显示空数据占位："暂无符合条件的数据"；汇总范围显示 0 条，数量和金额显示"—"。                               |
| 表单保存校验失败          | 必填项未填：`form-input` 加红框 + 下方红字提示；保存按钮**禁用直到全部必填校验通过**；充电电费/服务费为空：同上。               |
| 金额超出 / 类型错误       | input 红色边框 + "请输入非负数，最多2位小数"。                                                 |
| 项目切换未确认           | 用户取消 confirm 时，不切换、保持当前表单与筛选。                                                   |
| 详情记录已弱删除         | 按记录 ID 打开弹窗时若记录已被删，不打开弹窗并提示“记录不存在或已删除”。                       |
| 照片上传超 3 张         | 仅保留前 3 张（前端截断），其余丢弃；Toast 提示"最多上传 3 张"。                                      |
| 充电时间反转（结束 < 开始）  | submit 时校验，对应输入红框 + "结束时间不能早于开始时间"。                                          |
| 充电电费/服务费 = NaN   | 立即变 0；金额联动重算。                                                                  |
| 项目切换后原项目存在勾选记录 | 清空原项目勾选状态，禁止将不同项目的记录合并处理。 |
| 详情/编辑过程尝试切换项目 | 保持当前项目与记录不变，用户返回列表后才可切换。 |
