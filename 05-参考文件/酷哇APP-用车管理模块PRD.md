# 名词解释

| 名词     | 解释                                                        | 备注  |
| :----- | :-------------------------------------------------------- | :-- |
| 接车     | 司机在开始使用某车辆时，通过扫码的方式，建立司机与车辆的使用关系                          |     |
| 交车     | 司机在结束使用某车辆时，通过扫码的方式，解除司机与车辆的使用关系                          |     |
| 人车绑定   | 司机与车辆在一定时间范围内建立的使用关系                                      |     |
| 当前车辆任务 | 今日用车模块，指司机与绑定车辆今日需要完成的任务。检索条件为：司机 + 车牌号 + 今日时间            |     |
| 其他车辆任务 | 今日用车模块，指司机与其他车辆（剔除绑定车辆）今日需要完成的任务。检索条件为：司机 + 今日时间，剔除当前车辆任务 |     |

## 1 背景

在环卫作业中，车辆是一个重要的主体，围绕着车辆的使用全过程，能够串联起人（驾驶员或安全员）、任务、事件、成本费用等环节。因此，针对车辆进行全过程的监控管理是一个很重要的场景，目前公司在车辆使用过程中存在以下问题：

1. 车辆使用不规范，无法追踪车辆状态及使用情况
2. 车辆使用场景无配套 APP，数据仅停留在纸质台账
3. 部分已建设的子功能较为分散，且学习成本高
基于以上问题，希望从驾驶员和监管的角度出发，梳理车辆使用的全过程，形成一套车辆使用过程监管方案。
## 2 主要角色与职责

## 3 产品定义与说明
### 3.1 产品定义

功能主要搭载在移动端 - 酷哇 APP 应用中，主要面向非自动驾驶作业车辆驾驶员，目标是通过**场景化流程**，把驾驶员一天中围绕车辆发生的关键动作串起来，包括接车、任务执行、动态任务、水电油上报、故障报修、交车和工作回顾。在此基础上，实现管理层对驾驶员车辆使用过程的监管。

驾驶员有两种使用路径：

| 路径     | 说明                                        |
| ------ | ----------------------------------------- |
| 场景化主流程 | 先接车绑定车辆，直接进入任务页面，引导任务完成，其中可以穿插补给、报修、交车等动作 |
| 独立功能入口 | 未绑定车辆或者不进入场景化主流程，也可以单独进入日检、报修、水电油等功能      |

**接车绑定不是所有功能的绝对前置条件**，但它是场景化主流程的起点。未绑定时使用独立功能，必须在功能内明确车辆对象。

### 3.2 与现有系统的关系

| 系统名称     | 关系                          | 备注  |
| -------- | --------------------------- | --- |
| basis 平台 | 从 basis 平台中接入车辆信息、车型信息、项目信息 |     |
| 环卫云平台    | 与环卫云平台对接任务派发等信息             |     |
| 售后平台     | 与售后平台对接车辆维修工单的信息            |     |
| 权限系统     | 调用权限和用户信息                   |     |

### 3.3 产品边界
1. 本方案仅针对非自动驾驶的作业车辆进行场景拆解
2. 本方案仅针对车辆状态为正常的项目作业车辆，对于研发测试、维修中的车辆，不在此方案范畴

```
  -> 执行任务

  -> 结束任务
  -> 检查下一任务
  -> 交车

      -> 提醒项：允许交车
      -> 阻断项：不允许交车
  -> 今日回顾 + 今日任务 + 明日待办
```

## 6 功能详细设计

### 6.1 用车管理主页

定位：用车管理模块是非自动驾驶车辆司机的主要移动办公应用，其中包括了司机用车、任务执行、车务管理等常用功能

#### 6.1.1 框架

按照业务分组的方式对用车管理模块进行分组。

1. 今日用车：司机日常用车、执行当日任务的主界面，集成了司机用车过程中使用的常见功能
2. 任务管理：针对司机收到的不同类型任务进行分组展示，分为常规任务、应急任务、动态任务
3. 车务管理：目前主要针对能耗类费用数据上报，分为加油上报、加水上报、充电上报，支持查看已上报的记录
4. 维保管理：支持司机进行车辆故障报修和维修记录查看
5. 数据统计：以司机为维度进行出车、任务等数据统计
后续可能会根据实际情况对分组进行重新组织或更新
#### 6.1.2 项目切换功能
1. 用车管理模块右上角显示用户当前登录的项目名称，该项目名称与用户在功能操作时能够看到的数据资源关联
2. 默认显示为最近一次使用的项目，点击项目名称后弹出项目选取列表（当前用户关联的项目），支持搜索项目名称
#### 6.1.3 人车绑定关系显示

用户进入应用后，系统自动查询司机当前人车绑定状态，并显示在 “今日用车”卡片右侧

- 如果当前用户已绑定车辆，卡片右侧显示绑定的车辆牌照
- 如果当前用户已绑定车辆，但是该车辆网联设备离线，在车辆牌照下方叠加显示“设备已离线”
- 如果当前用户未绑定车辆，卡片右侧显示：“当前未绑定车辆”
#### 6.1.4 交互流程

1. 司机点击“今日用车”卡片，系统查询司机当前人车绑定状态和车辆可用状态：
	- 已绑定且车辆可用 → Toast 提示“进入今日用车”，跳转地图工作台。
	- 未绑定车辆 → 展示未绑定引导弹窗，不进入地图工作台。
2. 未绑定引导弹窗展示内容：
	- 提示文字：未查询到绑定车辆，请先扫码完成车辆绑定。
	- 去绑定车辆：打开**我的二维码**页面，使用既有绑定/扫码能力 → 绑定校验通过，完成人车关系的绑定，并进入今日用车模块。
	- 关闭：点击后关闭引导页。

### 6.2 今日用车模块

今日用车模块是司机已绑定车辆后的主要工作页面，能够实现路线导航、任务接收与执行、水电油上报、故障报修等功能。

进入今日用车模块前，需要进行绑定关系校验和车辆在线状态校验

#### 6.2.1 交互流程

##### 6.2.1.1 **当日有待办任务**

1. 初次进入今日用车模块后，此时还没有开始的任务
	- 顶部胶囊信息栏显示：绑定车辆车牌信息、车辆类型、任务情况、车辆状态（见 4.4 章节）
	- 底部显示任务卡片，默认显示该车辆 + 该司机时间排序最早的任务
	- 地图中默认显示当前车辆位置 + 任务卡片中的任务计划路线
2. 任务卡片中显示选中的任务的主要信息，包括路线、计划时间、类型、要求等。有以下按钮：
	- 导航按钮：以小图标按钮呈现，点击后调用高德地图 API 进行外部导航；
	- 开始任务：点击后进入需要校验是否满足开始任务条件。满足条件后，进入任务执行
		- 校验司机是否已绑定车辆
		- 该司机是否有其他正在执行的任务：
			- 若不通过，toast 提示“当前存在执行中任务”，任务卡片跳转为正在执行中的任务
		- 校验车辆是否是任务车辆
		- 校验车辆是否在线
		- 校验车辆的位置是否在路段范围
	- 任务详情：次按钮，点击后打开对应任务详情页面，查看详细要求
	- 更多按钮：点击后显示暂停任务、关闭任务按钮
		- 暂停任务：将当前正在执行中的任务暂停，在此状态下，用户可以开始执行其他任务
		- 关闭任务：将选中的任务予以关闭
3. 支持向上拉起打开今日待办任务清单，显示全部该司机的今日待办任务（可覆盖地图，也支持收起），也可以通过点击右侧“展开任务”达到相同的效果。
4. 今日待办任务清单分为**当前车辆任务**和**其他车辆任务**两组。组内清单中执行中任务优先，其次依次展示应急任务、动态任务、常规任务；已完成任务统一移动至组内列表底部。
	- 存在执行中任务 → 默认选中执行中任务。
	- 存在动态任务 → 动态任务优先展示，排在执行者任务后。
	- 仅存在常规任务、应急任务 → 按计划开始时间排序展示。
	- 无待办任务 → 展示空任务状态和交车引导。
5.  司机选中当前车辆某任务时，地图上显示该任务计划路线信息，任务卡片变为该任务的详细信息
6. 司机点击开始任务按钮，系统校验通过后，任务开始。此时收起今日待办任务清单
7. 任务执行状态下，地图上显示任务的计划路线信息（蓝色虚线）、车辆的实际移动轨迹（红色实线）、车辆位置，图层优先级递增。车辆位置点实时刷新，并在任务卡片中更新作业里程、已作业时长。有以下按钮：
	- 结束任务：主按钮，点击后进行**任务完成情况校验**
		- 校验通过后，结束任务。
			- 若**当前车辆任务**中有待开始的任务，则 toast 提示：已结束当前任务，已自动推送下一条。地图和任务卡片效果等同于选中推送的任务
			- 若**其他车辆任务**中有待开始的任务，则 toast 提示：当前车辆任务已结束，可交车或查看其他车辆任务
			- 若**当前车辆任务**和**其他车辆任务**中均无待开始任务，则 toast 提示：今日任务均已完成，可在归还车辆后交车
		- 校验未通过，无法结束任务，toast 提示原因
8. 司机在今日用车模块，若收到新派发的任务（常规、应急、动态任务）：
	- 轻提醒 → 地图上方 banner 提示，宽度与顶部车牌信息卡一致，信息靠左排列，内容格式为“任务类型 任务名称 距离 ”
	- 右侧固定“查看”按钮，点击后，展开今日待办任务清单，并选中该任务
9. 司机点击辅助按钮：
	- 复位：点击后地图焦点回到当前车辆位置
	- 水电油上报按钮：点击后打开底部弹窗，支持选择加油上报、加水上报、充电上报类型，点击后打开相应的上报页面。
	- 故障报修按钮：点击后打开故障报修页面
	- 交车按钮：点击后先进行**未完成任务校验**
		- **当前车辆任务**存在进行中未结束任务：无法交车。地图和任务卡片中显示该任务信息
		- 校验通过，则打开“我的二维码”页面进行扫码交车

##### 6.2.1.2 当日无待办任务
1. 进入今日用车模块后，toast 提醒：今日未查询到相关任务，可继续用车或者交车。
2. 若继续用车，地图显示车辆当前位置，并实时显示车辆轨迹；底部任务卡片为空，任务列表为空。
3. 支持进行复位、水电油填报、故障报修、交车等快捷操作
4. 用车过程中，如果该司机收到今日新的任务（常规、应急或者动态任务），在地图上方做轻提醒，并刷新任务卡片和任务列表
### 6.3 任务详情页面
##### 6.3.1.1 顶部地图

顶部为地图，地图要素随任务状态切换：

- 任务状态为待开始：仅显示计划路线 + 起终点标记

### 6.5 今日回顾页面

本页面主要是对司机今日的任务完成情况进行回顾，并列出明日待办任务，便于司机更好的安排工作。

#### 6.5.1 今日回顾卡片

展示任务完成数、轨迹里程、出车时长、水电油上报数、报修数。时间范围均限制在当日

- 任务完成数：指当前车辆任务完成数，不包含其他车辆
- 轨迹里程：指当前车辆从绑车 - 交车的轨迹里程数
- 出车时长：指当前车辆从绑车 - 交车的时长
- 水电油上报数：指当前车辆从绑车 - 交车的水电油上报单数
- 报修数：指当前车辆从绑车 - 交车的故障报修次数

#### 6.5.2 今日待办
1. 展示司机今日未完成的任务，包括常规任务、应急任务和动态任务
2. 检索条件为：司机 + 今日 + 所有任务类型 + 任务状态为待开始、执行中
3. 任务卡片分为两组
	- 当前车辆组：交车时**当前车辆任务**+ 任务状态为待开始、执行中
	- 其他车辆组：交车时**其他车辆任务**+ 任务状态为待开始、执行中
	- 卡片展示：计划时间、任务名称、路段、车牌号、任务类型
4. 点击卡片，支持打开任务详情

#### 6.5.3 明日待办
1. 展示司机明日的待办任务，包括常规任务、应急任务和动态任务
2. 检索条件为：司机 + 明日 + 所有任务类型
3. 任务卡片中展示：计划时间、任务名称、路段、车牌号、任务类型
4. 点击卡片，支持打开任务详情
5. 点击“返回首页”，回到用车管理页面
### 6.6 扫码绑车/交车

司机在绑定车辆和交车时，均需要使用到二维码来绑定/接触人与车的使用关系，考虑到酷哇 APP 中已有“我的二维码“功能，因此该二维码页面可以进行复用。

具体应用在以下场景：

1. 车辆绑定引导页：用户点击今日用车时，检测到未绑定车辆，在未绑定引导弹窗进行调用，用来建立用户与车辆的绑定关系
2. 交车：用户点击交车按钮后，若满足交车条件，进行调用，用来解除用户与车辆的绑定关系

#### 6.6.1 车辆绑定引导页
1. 在未绑定车辆下，打开二维码页面，二维码顶部为绑车说明
2. 扫码成功后，进行**人车关系校验**
	- 校验通过，完成司机与车辆的使用关系绑定
	- 校验不通过，toast 提示失败原因
3. 扫码完成后系统记录人员 + 时间 + 车辆 + 位置信息

#### 6.6.2 交车引导页
1. 已绑定车辆下，司机点击交车按钮，进行**未完成任务校验**，
	- 校验通过，打开二维码页面，二维码顶部为交车说明
	- 校验不通过，toast 提示：存在执行中任务，无法交车
2. 扫码完成后系统记录人员 + 时间 + 车辆 + 位置信息，并解除人与车使用关系的绑定
3. 打开今日回顾页面
