# 多角色用户地图页呈现与切换方案

> 适用范围：城市管家 APP「地图」Tab，针对一个账号绑定多个角色（如驾驶员 + 品质巡查）时，地图页面的呈现逻辑、角色切换机制与数据权限联动规则。
>
> 关联文档：`01-需求文档/城市管家应用框架.md`、`01-需求文档/城服配套APP方案拆解.md`、`03-高保真页面/map-workbench.html`

---

## 1 背景与核心结论

### 1.1 背景

城市管家 APP 采用「单应用 + 权限区分」架构（见 `城市管家应用框架.md` 第 5 行：不同角色共用一个入口，通过功能和数据权限进行划分）。框架文档涉及 6 类角色：项目经理、项目文员、驾驶员、环卫工、品质巡查、安全员。

其中地图 Tab 是场景分化最强的页面：

- **项目经理**：地图是「监控驾驶舱」，叠加作业/人员/车辆监控专题图
- **驾驶员**：地图是「任务执行台」，展示本人任务路线与车务上报入口
- **环卫工**：地图是「任务执行台」，展示本人任务路段与事件上报入口
- **品质巡查**：地图是「巡查执行台」，展示巡查路线与待复查问题点
- **安全员**：地图是「机器人监控屏」，展示机器人实时位置与告警

各角色**共用同一张底图，但叠加上层的业务图层和操作面板完全不同**。

### 1.2 核心结论

**多角色用户在地图页不应「只按主角色锁死展示」，而应采用「当前活动角色 + 场景切换」机制。**

- 地图页 = 统一底图 + 角色场景化图层 + 角色场景化操作面板
- 角色之间通过「场景切换」流转，而非退出重登
- 图层可叠加（信息可同时看），操作面板互斥（动作只能做一个）

---

## 2 为什么不用「主角色锁死」

### 2.1 候选方案对比

| 方案                  | 问题                            |
| ------------------- | ----------------------------- |
| 只按主角色展示，无法切换        | 兼任场景永远进不去；用户得退出重登换角色，体验断裂     |
| 主角色展示，需切换时退出重登      | 破坏单 APP 会话连续性；任务执行中途切角色会丢上下文  |
| 所有角色的图层/面板全堆在一张图上   | 信息过载；驾驶员不需要看机器人告警，安全员不需要看任务路线 |
| **当前活动角色 + 顶栏一键切换** | 每次只渲染一个角色的场景，干净；切换是轻量操作，不丢会话  |

**结论**：采用第四种。把「角色」当作地图页的一个**可切换上下文（context）**，而不是固定身份。

### 2.2 「当前活动角色」的判定与默认值

一个账号拥有角色集合 R（如 R = {驾驶员, 品质巡查}）。进入地图 Tab 时，按以下优先级决定默认渲染哪个角色场景：

1. **按当前是否有进行中任务推断**：若该账号有一条派给「驾驶员」角色的在途任务，默认进驾驶员场景；若有在途巡查任务，默认进巡查场景。最符合「用户此刻想干什么」。
2. **无在途任务时，按主角色**：主角色在账号配置里设定（通常是其岗位主责）。
3. **记住上次离开地图时的角色**：`localStorage` 记一个 `lastMapRole`，下次进地图直接恢复，减少重复选择。

## 3 地图页三段式结构

地图页拆成三个解耦的层，角色差异只体现在后两层，底图完全复用：

```
┌─────────────────────────────────────────┐
│ 顶栏：[当前活动角色 ▾]  [图层⚙]  [定位] │  ← 角色切换器在这
├─────────────────────────────────────────┤
│                                         │
│         共享底图（地图瓦片）            │  ← 全角色共用，零差异
│   + 角色业务图层（POI/路线/机器人）     │  ← 按活动角色渲染
│                                         │
├─────────────────────────────────────────┤
│ 底部操作面板（按角色场景化）            │  ← 差异最大的地方
│  驾驶员：任务执行控制台                  │
│  巡查员：巡查任务控制台                  │
│  项目经理：监控统计面板                  │
│  安全员：机器人告警面板                  │
└─────────────────────────────────────────┘
```

### 3.1 底图层：全角色共用

地图瓦片、定位、缩放、图层开关、导航等基础能力，所有角色一模一样。这是单 APP「页面可重复使用率」最高的部分，只写一遍。

### 3.2 业务图层：按当前活动角色叠加

同一张底图上，不同角色叠不同的业务图层（可多选共存）：

| 角色 | 叠加的业务图层 |
|---|---|
| 项目经理 | 作业监控图层 + 人员监控图层 + 车辆监控图层（可切换的「专题图」，即框架文档所述「共用一个地图，通过切换专题图形式」）|
| 驾驶员 | 本人任务路线图层 + 途经 POI（加油/加水/充电站）图层 |
| 环卫工 | 本人任务路段图层 + 事件上报点图层 |
| 品质巡查 | 巡查路线图层 + 待复查问题点图层 |
| 安全员 | 机器人实时位置图层 + 告警热力图层 |

**关键点**：兼任角色的用户，图层可以叠加显示。例如驾驶员 + 巡查员，可以在地图上同时看到本人的驾驶任务路线和待复查问题点——这是多角色的价值，单角色 APP 做不到这种叠加。但**操作面板不能叠加**，因为操作动作是互斥的（见 3.3）。

### 3.3 操作面板：按当前活动角色，互斥渲染

底部面板承载「当前要做什么动作」，必须互斥，一次只显示一个角色的面板：

| 当前活动角色 | 底部操作面板 |
|---|---|
| 驾驶员 | 任务执行控制台（开始/暂停/完成、水电油上报入口）—— 对应框架文档「地图 Tab - 任务执行」 |
| 环卫工 | 任务执行控制台（开始/暂停/完成、事件上报入口） |
| 品质巡查 | 巡查任务控制台（检查项打分、问题上报、整改复查） |
| 项目经理 | 监控统计面板（人员/车辆/作业实时数） |
| 安全员 | 机器人告警 / 应急工单处理面板 |

**互斥原因**：操作面板承载的是「当前焦点动作」，一个人同一时刻只能执行一种动作，叠加没有意义还会误触。

> **核心设计规则**：图层可以并存（信息可同时看），面板必须互斥（动作只能做一个）。这是设计多角色地图页最关键的一条规则。

## 4 角色切换的三种入口

### 4.1 顶栏角色切换器（主动切换）

地图顶栏放一个「当前活动角色」下拉（如 `驾驶员 ▾`），点开列出该账号拥有的全部角色。切换后：

- 业务图层按「切换后是否保留旧图层」处理，建议**保留并叠加**（见 3.2，这正是多角色的价值）
- 操作面板立即替换为新角色面板
- 底图不动，定位不动

### 4.2 任务/工单驱动的隐式切换（被动切换，推荐作为主路径）

多数情况下用户不需要主动选角色，而是被一条具体任务「带」进对应角色场景：

- 首页待办里点一条「驾驶任务」→ 自动切到地图 + 驾驶员场景 + 定位到任务起点
- 收到一条巡查任务推送 → 自动切到地图 + 巡查员场景
- 收到应急工单 → 自动切到地图 + 安全员场景

**这条路径比顶栏切换更重要**，因为一线人员的真实使用动线是「被任务驱动」，不是「先想我是谁再打开地图」。隐式切换的本质是：任务的角色属性决定了地图的活动角色，用户甚至感知不到「切换角色」这个动作。

### 4.3 会话连续性保障

切换角色**不退出登录、不清空定位、不丢地图缩放层级**。只切换「业务图层组合 + 操作面板 + 数据权限范围」这三样。实现上，角色上下文是一个内存对象 `activeRoleContext`，切换时只重渲染图层和面板组件，底图实例保持不动。

## 5 数据权限随活动角色联动变化

这是最容易漏的一点。地图上看到的 POI、人员、车辆、任务点，**数据范围要随当前活动角色变化**：

| 同一个账号，切到角色 | 地图数据可见范围 |
|---|---|
| 驾驶员 | 只看派给本人的任务路线和车辆 |
| 品质巡查 | 看派给本人的巡查路线 + 待复查问题点 |
| 项目经理 | 看全项目所有人员/车辆/作业实时位置 |
| 安全员 | 看全项目所有机器人位置和告警 |

切换角色 = 切换数据权限上下文。同一个「人员监控图层」，驾驶员角色下不渲染（无权看他人），项目经理角色下渲染全项目人员。**图层组件是同一套，数据源按角色过滤**——与单 APP「靠数据权限隔离」的总体架构一脉相承。

## 6 边界与异常场景

| 场景          | 处理规则                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| 角色被管理员临时取消  | 切换器里灰显该角色并提示「该角色权限已变更」，不允许切入，避免看到无权数据                                        |
| 进行中任务时强制切角色 | 若驾驶员正在执行一条任务，切到巡查员角色时弹确认「当前有未完成任务，切换将暂停任务执行」，避免任务状态丢失。暂停态可恢复                 |
| 只有单角色的账号    | 顶栏不显示角色切换器（或显示但只有一项），减少干扰——大部分一线人员其实是单角色，不要为他们强加切换器                          |
| 角色场景配置缺失    | 某账号有角色但未分配地图场景（如文员角色无地图场景），切到该角色时地图页提示「该角色无需使用地图，请前往服务 Tab」，并引导跳转，而不是渲染一个空地图 |
| 离线/弱网切换     | 角色上下文切换是本地状态变更，不依赖网络；但切换后图层重新拉取数据可能失败，需有缓存兜底 + 失败重试提示                        |

## 7 落地建议（结合现有 map-workbench.html）

现有的 `03-高保真页面/map-workbench.html` 已实现项目经理视角的「专题图切换」（作业监控/人员监控/车辆监控）和驾驶员的「任务执行控制台」。多角色方案的演进路径：

1. **把「专题图切换」抽象成更上层的「角色场景切换」**：专题图是项目经理角色内部的图层切换；角色场景切换是更外层的、跨角色的切换。两者是嵌套关系——先选角色（外层），角色内部再选专题图（内层，仅管理类角色有）。
2. **操作面板组件化**：把任务执行控制台、巡查控制台、监控统计面板做成可插拔组件，底部面板容器按 `activeRole` 动态挂载。
3. **顶栏加角色切换器**：仅当账号 `roles.length > 1` 时显示。

## 8 待确认项

以下问题影响多角色地图方案的细化，需与业务方对齐：

1. **角色是否可兼任/切换机制**：一个账号能否同时绑定多个角色（如巡查员 + 驾驶员），兼任时权限取并集还是需手动切换？`城服配套APP方案拆解.md` 第 75 行暗示巡查员会与车辆关联，但未明确机制。
2. **数据权限的组织粒度**：项目经理看「项目级」、主管看「片区级」、驾驶员看「个人级」，这个层级模型文档未给，需确认。
3. **主角色的判定来源**：主角色是账号配置里写死的字段，还是按最近活跃角色推断？
4. **角色切换是否记入操作日志**：出于安全审计，切换角色是否需要留痕？

---

## 附：一句话总结

多角色用户的地图页：**底图共享、图层可叠加、面板按当前活动角色互斥、切换靠任务驱动为主/顶栏切换为辅、数据权限随角色联动**。不锁主角色，也不把所有角色堆一屏，而是让角色成为一个可切换的地图上下文。
