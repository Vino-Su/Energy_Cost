# 名词解释

| 名词  | 解释                                 | 备注  |
| :-- | :--------------------------------- | :-- |
| 接车  | 驾驶员在开始使用某车辆时，通过扫码的方式，建立驾驶员与车辆的使用关系 |     |
| 交车  | 驾驶员在结束使用某车辆时，通过扫码的方式，解除驾驶员与车辆的使用关系 |     |

## 1 背景

在环卫作业中，车辆是一个重要的主体，围绕着车辆的使用全过程，能够串联起人（驾驶员或安全员）、任务、事件、成本费用等环节。因此，针对车辆进行全过程的监控管理是一个很重要的场景，目前公司在车辆使用过程中存在以下问题：

1. 车辆使用不规范，无法追踪车辆状态及使用情况
2. 车辆使用场景无配套 APP，数据仅停留在纸质台账
3. 部分已建设的子功能较为分散，且学习成本高
基于以上问题，希望从驾驶员和监管的角度出发，梳理车辆使用的全过程，形成一套车辆使用过程监管方案。
## 2 主要角色与职责

| 角色      | 职责                          | 备注  |
| :------ | :-------------------------- | :-- |
| 作业车辆驾驶员 | 驾驶车辆；打卡；待办事项；执行任务；车务信息；任务回顾 |     |
| 管理员     | 异常监控；作业排班；事件分配              |     |

## 3 产品定义与说明
### 3.1 产品定义

本方案面向非自动驾驶作业车辆驾驶员，目标是通过**场景化流程**，把驾驶员一天中围绕车辆发生的关键动作串起来，包括接车、日检、任务执行、动态任务、异常提醒、水电油上报、故障报修、交车和工作回顾。在此基础上，实现管理层对驾驶员车辆使用过程的监管。

驾驶员有两种使用路径：

| 路径     | 说明                                     |
| ------ | -------------------------------------- |
| 场景化主流程 | 先接车绑定车辆，再由系统引导完成日检、任务、异常处理、补给、报修、交车等动作 |
| 独立功能入口 | 未绑定车辆时，也可以单独进入日检、报修、水电油等功能，但在功能内必须选择车辆 |

也就是说，**接车绑定不是所有功能的绝对前置条件**，但它是场景化主流程的起点。未绑定时使用独立功能，必须在功能内明确车辆对象。

后续功能主要搭载在移动端 - 酷哇 APP- 城市管家应用中

### 3.3 产品边界
1. 本方案仅针对非自动驾驶的作业车辆进行场景拆解
2. 本方案仅针对车辆状态为正常的项目作业车辆，对于研发测试、维修中的车辆，不在此方案范畴

## 5 工作流程图
### 5.1 驾驶员工作日流程图

```
进入工作台
  -> 接车绑定
  -> 车辆可用性校验
      -> 不通过：禁止出车，停止后续主流程
      -> 通过：进入今日待办
  -> 车辆日检
      -> 日检完成后，允许接受/执行任务
  -> 接受排班任务
  -> 开始任务
  -> 执行任务
      -> 接收提醒类异常
      -> 处理动态任务
      -> 补给上报
	  -> 故障报修
  -> 结束任务
  -> 检查下一任务
  -> 交车
      -> 检查未完成事项
      -> 提醒项：允许交车
      -> 阻断项：不允许交车
  -> 今日回顾 + 明日待办
```

## 6 非自动驾驶作业车辆场景拆解

对于非自动驾驶作业车辆，均配备有驾驶员。围绕着驾驶员在车辆使用过程中的常见业务场景，拆分了以下子场景。

### 6.1 驾驶员接车

#### 6.1.1 接车扫码

接车是驾驶员用车的第一步，驾驶员可以通过展示个人二维码或者扫描车辆二维码的方式完成接车。

- 使用车辆摄像头扫描驾驶员二维码：适用于车辆装备有摄像头的情形
- 使用手机摄像头扫描车辆二维码：适用于车辆无摄像头，有车辆二维码的情形，作为备选方案
以上两种方式均能作为驾驶员与车辆的使用关系绑定的触发入口。扫码完成后系统记录人员 + 时间 + 车辆 + 位置信息，并进行车辆可用性校验，校验通过后，完成驾驶员与车辆的使用关系的绑定。
考虑到驾驶员可能在当天多次扫描二维码，因此在此做以下逻辑判断：

| 当前状态                    | 扫码车辆 | 系统动作                          |
| ----------------------- | ---- | ----------------------------- |
| 驾驶员无绑定车辆，车辆也未被绑定        | 当前车辆 | 判定为接车                         |
| 驾驶员无绑定车辆，但车辆已被他人绑定      | 当前车辆 | 禁止接车，提示车辆已被占用                 |
| 驾驶员已绑定 A 车，B 车扫描该驾驶员个人码 | B 车  | 不自动换车，提示需先交 A 车               |
| 驾驶员已绑定 A 车，但 A 车存在未结束任务 | A 车  | 进入交车检查，阻断交车                   |
| 驾驶员已绑定 A 车，无阻断项         | A 车  | 触发交车确认，确认无误后进入未完成事项检查，详见 6.7 章节 |

为避免驾驶员误扫码，若系统判定为交车动作，APP 需要弹窗进行二次确认，驾驶员确认交车后，执行后续动作。

> 目前驾驶员的二维码包含信息：设备号、用户名、当前经度、当前纬度、角色
#### 6.1.2 考勤记录

驾驶员的考勤可以与接车、交车的动作相关联，通过扫码的方式获取驾驶员的打卡信息，具体逻辑如下：

```
当天首次成功接车
  -> 如无考勤记录，生成或更新上班考勤事件
  -> 如已有考勤记录，以最早时间为准
  -> 创建人车绑定关系

当天成功交车
  -> 关闭人车绑定关系
  -> 可作为下班考勤候选时间
  -> 按照最晚的交车时间进行更新
```

也就是说，对于驾驶员来说，只需要关注接车、交车的扫码即可，系统会自动进行人 - 车关系的绑定以及驾驶员日常考勤事件的记录

#### 6.1.3 可用性校验

驾驶员在接车扫码成功后，系统需要调取车辆信息并进行车辆可用性校验：

- 证照、保险、年检已到期
- 车辆故障未修复完成
- 该车辆已被他人使用
- 当前用户存在正在使用的车辆

若可用性校验不通过，则不建立驾驶员与车辆的使用关系，也不进入到场景主流程，并在 APP 中进行相应的提示。驾驶员可更换其他车辆或者取消已绑定的车辆进行作业。

若可用性校验通过，则可建立驾驶员与车辆的使用关系，并进入到场景主流程。APP 自动检索该车辆与该驾驶员相关联的今日待办任务或事项，如

- 车辆日检
- 排班任务
- 维保任务
- 保险到期预警
- ......
在待办任务或事项列表中，驾驶员能看到今日需要做的事情，同时也避免了人找功能

### 6.2 车辆日检

依据项目要求，作业车辆每日在使用前，应该进行车辆的日检，驾驶员依据规定好的检查项对车辆的状态进行逐一比对。检查项可以按照对车辆的影响程度分为以下几类

- **禁止出车**：出现了无法启动或者影响行车安全的问题
- **允许出车但是需报修**：出现了问题，但是不影响作业或者和行驶，可以作业完成后进行维修
- **仅记录**：出现了问题，但是不影响日常使用，可以立即修复
对于检查不通过的检查项记录原因并拍照，并最终评估是否影响出车作业。具体车辆日检的检查项需要与项目方进行讨论后形成
根据最终的车辆日检结果，有以下几种途径：
- 如果禁止出车，则驾驶员一键报修并推送至售后系统。同时将车辆维修信息同步至环卫云平台，通知项目经理进行任务调整
- 如果允许出车但是需报修，驾驶员一键报修并推送至售后系统，并预约维修时间。可以继续出车并进入下一场景
- 对于检查通过或者说某些检查项仅记录的情形，则可以出车并进入下一场景

### 6.3 执行排班任务

执行排班任务是驾驶员操作作业车辆最为常见的场景，也是驾驶员的主线任务。APP 会自动汇集当前车辆被安排的任务（包括日常任务和应急任务，其中应急任务的优先级高），驾驶员能够查看任务的具体信息如时间、路段、作业要求等

1. **接受任务**：驾驶员查看任务后并确认接受。支持导航至任务路段
2. **开始任务**：驾驶员到达任务地点后开始执行任务。开始任务前需要校验车辆的位置是否在路段范围以及是否在计划时间前到达指定地点
3. **执行任务**：驾驶员按照要求开展作业任务，期间车辆的实时状态数据会传输至环卫云平台，并实时监控，如果触发异常事件，系统会生成异常事件记录，APP 会对异常事件进行播报，提醒驾驶员进行规范作业
4. **结束任务**：驾驶员点击结束任务，系统对驾驶员的任务完成情况进行检查：
	- 路线覆盖度：计划路线与实际轨迹是否吻合
	- 时间校验：是否在计划时间内完成任务
5. **任务推送**：结束上一任务后，系统会检查驾驶员是否还有待完成的任务，如果有的话，会自动推送下一个任务信息；如果没有，驾驶员可以导航至停放场地，进行还车操作
### 6.4 执行动态任务

动态任务是车辆作业过程中，依据摄像头智能识别的结果产生的任务，主要针对垃圾遗漏等问题。

在驾驶员正常执行任务的过程中，如果系统接收到了动态任务，会按照责任划分推送至相应驾驶员 APP 页面，并高亮显示，同时考虑到驾驶员可能在行驶过程中，可以通过语音播放的方式播放。

驾驶员按照开始任务 - 执行任务 - 结束任务的流程执行动态任务。摄像头会对已完成的路段再次识别，如果未识别出问题，则该动态任务闭环。

执行动态任务可作为执行排班任务中的插曲，不影响主线排班任务的开展。可在执行动态任务完毕后，继续执行排班任务

### 6.5 故障报修

车辆行驶过程中，可能会遇到车辆故障。按照对作业的影响程度和车辆故障严重程度，可以分为以下几类：

- **影响作业，无法自行返回**：作业终止，驾驶员一键报修，等待维修人员到达现场进行维修
- **影响作业，可自行返回**：作业终止，驾驶员导航至维修场地后，一键报修
- **不影响作业**：继续执行任务，驾驶员一键报修，并可预约维修时间
驾驶员发起一键报修后，可填报故障描述、期望维修时间、是否现场维修等信息，工单实时推送至售后系统，并通知售后维修人员处理
对于处于维修状态的车辆，会将车辆的状态通知环卫云系统，对应环卫云作业排班的资源需要更新
### 6.6 水电油上报

车辆在使用过程中，水、电、油的补给也是正常运行必不可少的一部分。采集水电油的使用及费用信息对于项目成本控制和分析具有重要意义。

- **加水上报**：考虑到当前加水点很难实现单次结算，因此支持驾驶员手动填报水量、估算水费和里程表信息
- **充电上报**：针对采用充电桩充电的车辆，驾驶员需要上传充电明细截图和里程表照片，系统自动解析后，完成充电明细上报。如果解析不成功或者无充电明细截图，支持手动填写。采集主要信息有：充电量、单价、费用、里程数、充电完成时间
- **加油上报**：一般采用油卡支付，驾驶员需要上传加油小票和里程表照片，系统自动解析后，完成加油明细上报。采集主要信息有：加油量、单价、费用、里程数、加油时间
### 6.7 驾驶员交车

当驾驶员完成当日任务后，可导航返回场地，并进行交车操作。

1. 驾驶员打开个人二维码或者扫描车身二维码
2. 扫描成功后，系统记录人员 + 时间 + 车辆 + 位置信息，根据 6.1.1 章节的判定逻辑判断是否触发交车确认
	- 触发交车确认：弹窗二次确认，驾驶员手动确认后，进入下一步
	- 未触发交车确认：显示具体的阻断信息
3. 系统检查当前是否存在未完成事项（未结束任务、未处理动态任务、未处理报修工单等）
	- **存在未完成事项**：列出未完成事项列表，支持驾驶员进一步操作。
		- 存在阻断项：如存在未结束的任务，无法交车，需要先结束或者异常关闭
		- 仅存在提醒项：如存在未完成异常，做提醒，可以交车，并解除驾驶员与当前车辆的使用关系
	- **不存在未完成事项**：完成交车，并解除驾驶员与当前车辆的使用关系
4. 系统自动检索并生成今日驾驶员的工作数据及明日计划
5. 驾驶员退出 APP，结束当天工作
通过以上交车流程，从而形成驾驶员当日工作的统一收口
### 6.8 异常监控

车辆在行驶过程中，车辆的智能网联设备会实时上传车辆的运行数据（如时间、经纬度、速度等），出于安全和质控角度考虑，系统对车辆的异常运行进行实时监控，具体异常事件种类及规则如下：

1. **车辆使用异常**：车辆未按照用车规范使用的行为
	- 车辆行驶未关联驾驶员：车辆在行驶状态下，但是未找到关联的驾驶员（该异常可推送至项目经理）
	- 车辆长时间未交车：车辆出现了跨天未交车的情况（具体时间可以结合实际修改）
2. **车辆合规异常**：车辆不满足上路条件
	- 年检到期
	- 保险到期
	- 牌照到期
3. **车辆日检异常**：该异常类型主要适用于车辆未走主流程用车的情况
	- 行驶车辆未日检：行驶状态下的车辆当天无日检记录
4. **任务执行异常**：该异常类型仅针对处于“执行中”任务状态的车辆生效
	- 轨迹偏差过大：车辆的实际路线与计划路线与偏差过大
	- 轨迹覆盖度不足：任务完成后，车辆的轨迹覆盖与计划路线偏差过大
	- 动态任务未响应/未闭环：对于指派的动态任务未响应或完成
5. **超速行驶**：车辆的行驶速度超过限值
6. **超时停靠**：车辆在某一区域停靠时间超过阈值
7. **限行区行驶**：车辆在限行区内行驶
以上异常规则，可以按照项目需求进行启用或个性化配置。

一旦触发异常事件规则，环卫云平台会生成异常事件记录，并根据异常事件的类型采用不同的处理策略：

| 异常大类   | 异常事件         | 驾驶员端处理    | 管理端处理       |
| ------ | ------------ | --------- | ----------- |
| 使用异常   | 车辆行驶未关联驾驶员   | -         | 推送项目经理核查    |
| 使用异常   | 车辆长时间未交车     | 提醒交车      | 推送项目经理核查    |
| 合规异常   | 年检/保险/牌照到期   | 接车强拦截     | 推送管理处置      |
| 日检异常   | 行驶车辆未日检      | 提醒并记录     | 后台复核        |
| 任务异常   | 轨迹偏差、轨迹覆盖度不足 | 轻微提醒，严重记录 | 任务完成复核      |
| 安全异常   | 超速行驶、限行区行驶   | 强提醒自纠     | 多次可推送项目经理核查 |
| 停靠异常   | 超时停靠         | 提醒并记录     | -           |
| 动态任务异常 | 未响应/未闭环      | 提醒处理      | 推送项目经理核查    |

## 7 附录
### 7.1 待定内容

1. 执行排班任务时，是否需要考核时间、定位
2. 一般排班的时间会有富余吗，会很紧张吗

6. 需要进一步明确动态任务是否必须响应，是否有闭环机制

### 7.2 驾驶员动作拆解

| 阶段  | 驾驶员动作          | 产品含义                    |
| --- | -------------- | ----------------------- |
| 开工前 | 登录 APP / 进入工作台 | 进入驾驶员工作场景               |
| 接车  | 扫车码或展示人码       | 完成人车绑定                  |
| 接车  | 确认车辆信息         | 防止扫错车、用错车               |
| 接车  | 车辆可用性校验        | 证照、保险、年检、维修状态、是否已被他人绑定  |
| 出车前 | 查看今日待办         | 日检、排班任务、维保提醒、补给提醒、预警事项  |
| 出车前 | 车辆日检           | 检查车况，异常项拍照、说明           |
| 任务前 | 接收任务           | 确认任务时间、路段、要求            |
| 任务前 | 导航至作业点         | 降低找路成本，也为到达校验提供依据       |
| 任务中 | 开始任务           | 记录任务开始时间、位置、车辆状态        |
| 任务中 | 按路线作业          | 系统采集轨迹、速度、停靠、设备状态       |
| 任务中 | 接收异常提醒         | 超速、偏航、未日检、停靠过久等         |
| 任务中 | 处理动态任务         | 垃圾遗漏、临时事件、应急作业          |
| 任务中 | 暂停/恢复任务        | 处理加水、避让、等待、设备调整等真实场景    |
| 任务中 | 水电油上报          | 加油、充电、加水、里程、费用凭证        |
| 任务中 | 故障报修           | 不影响作业、影响但可返回、无法返回三类     |
| 任务后 | 结束任务           | 校验路线覆盖、时间、完成状态          |
| 任务后 | 接收下一任务         | 形成连续作业引导                |
| 收工前 | 返回停车点          | 可导航，可校验停放区域             |
| 收工前 | 处理未完成事项        | 未提交补给、未结束任务、未确认异常、未上传照片 |
| 交车  | 扫码交车           | 解除人车绑定                  |
| 交车  | 生成今日回顾         | 工时、任务、里程、异常、补给、报修、明日计划  |
| 下班  | 退出工作状态         | 完成当天闭环                  |
