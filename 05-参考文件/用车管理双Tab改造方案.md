## 1 改造背景与现状

### 1.1 现状信息架构（三层门户结构）

```
APP 底部 Tab（消息 / 工作台 / 我的）
  └─ 工作台 home.html → 点击「用车管理」卡片
       └─ 用车管理主页 vehicle-management.html
          （5 个分组：今日用车 / 任务管理 / 车务管理 / 维保管理 / 数据统计）
            └─ 点击「今日用车」卡片 → 绑定校验 → 地图工作台 map-workbench.html
```

### 1.2 现状问题

1. **主流程埋得过深**：司机每次干活需跨 3 次跳转 + 1 次卡片校验才能到达地图工作台，而地图工作台才是他一天里 90% 时间停留的页面。
2. **门户与执行割裂**：用车管理主页是"入口列表"，地图工作台是"干活界面"，二者被一次额外跳转隔开，未体现"场景化主流程是主线"（PRD 3.1）。
3. **绑定校验前置过死**：未绑定车辆时完全无法进入地图工作台，与 PRD 3.1"接车绑定不是所有功能的绝对前置条件"存在张力。

### 1.3 使用角色

| 角色         | 在本改造中的关注点                   |
| ---------- | --------------------------- |
| 作业车辆驾驶员    | 打开即进入干活页面；未绑定时也能查看任务；随时可退出  |
| 项目经理 / 管理员 | 监管留痕连续性不受影响（轨迹、任务、交车记录口径不变） |

---

## 2 改造目标与价值

| 维度     | 说明                                   |
| ------ | ------------------------------------ |
| 主流程前置  | 进入用车管理即进入地图工作台，干掉 2 层跳转              |
| 信息架构升级 | 由"门户式"升级为"应用式"，兑现 PRD 3.1 的两条使用路径    |
| 心智清晰   | 地图 = 做（执行），服务 = 找/查（入口），双 Tab 心智模型直观 |
| 校验合理化  | 绑定校验从"进入门槛"下沉为"开始任务门槛"，允许未绑定先看任务     |
| 监管连续   | 子页面、上报页、今日回顾、留痕规则全部不动，监管数据口径不变       |

## 3 核心方案（已确认决策）

### 3.1 独立应用形态 —— 模式 A

进入用车管理后，**底部 Tab 整体替换**为用车管理自己的「地图 / 服务」；APP 原有的「消息 / 工作台 / 我的」暂时隐藏，退出用车管理后恢复。

```
APP 工作台 home.html → 点击「用车管理」
  └─ 用车管理（独立应用，底部 Tab = 地图 / 服务）
       ├─ 地图 Tab（默认进入，承载原"今日用车 + 地图工作台"全部内容）
       └─ 服务 Tab（分组宫格，承载原用车管理主页的子功能入口）
```

### 3.2 双 Tab 定位与命名

| Tab     | 定位                                   | 承载内容                                                       |
| ------- | -------------------------------------- | -------------------------------------------------------------- |
| 地图    | 司机主工作页，打开即干活               | 地图、任务执行、水电油上报、故障报修、交车（原 map-workbench） |
| 服务    | 子功能入口，按业务分组                 | 任务管理 / 车务管理 / 维保管理 / 数据统计（原 vehicle-management 分组） |

> 命名采用「地图 / 服务」。"服务"避免与 APP 层「工作台」重名，且语义更贴合"车务/维保/统计入口"。

### 3.3 "今日用车"概念的变化

改造后**"今日用车"不再作为服务 Tab 里的一个卡片**。其内容（绑定校验 + 地图工作台）整体下沉为**地图 Tab**。"今日用车"作为入口卡片从服务 Tab 移除。

## 4 详细设计

### 4.1 进入与退出机制

#### 4.1.1 进入

- APP 工作台 `home.html` 的「用车管理」卡片入口保留，点击后进入用车管理（独立应用），默认落在地图 Tab。
- 入口卡片**保持现状，不强化**（不新增车牌/任务数预览）。

#### 4.1.2 退出（返回按钮，模式 A 必需）

由于底部 Tab 已被「地图 / 服务」替换，APP 的消息/我的需通过**退出**回到。退出入口恒定可见：

| Tab    | 退出入口位置                         | 目的地                       | 语义                     |
| ------ | ------------------------------------ | ---------------------------- | ------------------------ |
| 地图   | 顶部车辆信息栏最左侧「返回」图标     | `home.html`（APP 工作台）    | 退出用车管理             |
| 服务   | 顶部导航栏左侧「返回」图标           | `home.html`（APP 工作台）    | 退出用车管理             |

> 返回按钮的目的地由现状的 `vehicle-management.html` 统一改为 `home.html`。
> 退到 home.html 后，APP 底部 Tab「消息/工作台/我的」恢复激活态。

### 4.2 地图 Tab（默认页）

#### 4.2.1 状态分支（绑定校验落点下沉）

| 状态                       | 地图 Tab 表现                                                                 |
| -------------------------- | ----------------------------------------------------------------------------- |
| 已绑定且车辆可用           | 完整地图工作台：车辆位置 + 任务路线 + 实时轨迹 + 任务卡片 + 工具组（执行态） |
| 未绑定                     | 可进入：地图展示司机名下任务点分布；任务列表按车辆平铺分组；导航、查看可用    |
| 已绑定但车辆不可用         | 提示不可用原因，不进入执行（沿用 PRD 5.1.3）                                  |
| 已绑定但当日无待办任务     | 空任务态 + 交车/补给出入口（沿用 PRD 6.2.1.2）                                |

#### 4.2.2 绑定校验落点变更（核心规则调整）

| 动作           | 原规则（PRD F01 / 5.1.3）         | 新规则                                       |
| -------------- | --------------------------------- | -------------------------------------------- |
| 进入地图 Tab   | 未绑定 → 阻断，引导绑定           | 未绑定 → **允许进入**，可查看所有任务        |
| 开始任务       | 校验绑定关系                      | **不变**：未绑定 → toast「请先绑定车辆」拦截 |
| 交车           | 校验绑定                          | 不变                                         |

> 校验从"进入门槛"降级为"开始任务门槛"，兑现 PRD 3.1"绑定是场景化主流程的起点，但不是所有功能的绝对前置"。

#### 4.2.3 任务列表分组（按车辆，当前车辆优先）

地图 Tab 底部任务抽屉/列表改为**以车辆为分组维度**：

| 绑定状态 | 分组方式                                                     |
| -------- | ------------------------------------------------------------ |
| 已绑定   | 第 1 组 = 当前车辆（主色 #1677ff 高亮置顶）；其后按其他车辆逐辆分组 |
| 未绑定   | 无当前车辆，全部任务按所属车辆平铺分组                       |

- 组内排序沿用 PRD 5.3.2：执行中 → 应急 → 动态 → 常规；同类型按计划开始时间升序；已完成置底。
- 当车辆分组较多、列表较高时，支持以**弹窗形式拉起**完整任务列表，便于浏览全部任务。

#### 4.2.4 未绑定态地图展示（已确认）

未绑定时无"当前车辆位置"，地图**展示司机名下所有任务点的地理分布**（聚合标记），让司机一眼看到任务分布，辅助决定先去哪辆、或先绑定哪辆。

#### 4.2.5 工具组与操作

定位回正、水电油上报、故障报修、交车等右侧悬浮工具**沿用现状**不变。其中：
- 水电油上报 / 故障报修：未绑定时按各自独立功能规则（需选择车辆）。
- 交车：未绑定无可交车辆，按 PRD 5.7.3 拦截。

### 4.3 服务 Tab（分组宫格）

沿用原 `vehicle-management.html` 的分组与宫格样式，**移除"今日用车"分组/卡片**，保留：

| 分组     | 入口                                                       |
| -------- | ---------------------------------------------------------- |
| 任务管理 | 常规任务、应急任务、动态任务                               |
| 车务管理 | 加油上报、加水上报、充电上报、上报记录                     |
| 维保管理 | 故障报修、维修记录                                         |
| 数据统计 | 出车统计、任务统计                                         |

- 任务管理三个入口的查询口径**不变**：当前驾驶员名下、跨车辆、按任务类型查询（PRD 5.3.5.2）。
- 顶部导航栏：标题"服务"，左侧退出返回按钮（见 4.1.2）。
- 项目切换（PRD 6.1.2）入口**放置于服务 Tab 顶部**，复用 home.html 项目切换器。

### 4.4 双视角任务说明（避免数据打架）

任务数据同源，两个地方切不同维度，**不可合并**：

| 位置             | 分组维度   | 视角                         | 说明                       |
| ---------------- | ---------- | ---------------------------- | -------------------------- |
| 地图 Tab 任务列表 | **车辆**   | 执行视角："每辆车今天干啥"   | 服务执行，含开始/结束操作  |
| 服务 Tab 任务管理 | **任务类型** | 查询视角："有哪些常规/应急/动态" | 跨车辆查询，详情只读       |

> 同一批任务的两种视图。需在产品文案/引导上让司机理解二者关系，避免"为什么数字不一样"的困惑（实际是同一批数据的不同切面）。

### 4.5 交车闭环

```
地图 Tab 点击「交车」
  → 前置校验（仅拦截进行中未结束任务，PRD 7.10 不变）
  → 二维码扫码交车（解除人车绑定）
  → 今日回顾页（today-review.html）
  → 「返回首页」
  → 回到地图 Tab（此时未绑定 → 接 4.2.1 未绑定态，可查看所有任务）
```

| ------------------------------------------ | ---------------------------------------------------------------------- |

## 8 验收标准（初步）

1. 从 APP 工作台点击「用车管理」，**直接进入地图 Tab**，底部 Tab 显示为「地图 / 服务」，APP 原底部 Tab 隐藏。
2. 地图/服务两个 Tab 顶部均有「返回」按钮，点击回到 APP 工作台 `home.html`，APP 底部 Tab 恢复。
3. 已绑定且车辆可用时，地图 Tab 完整呈现地图工作台（车辆、路线、轨迹、任务卡片、工具组）。
4. 未绑定时可进入地图 Tab，可查看按车辆分组的所有任务，可导航、查看详情；点击「开始任务」被拦截并提示绑定。
5. 地图 Tab 任务列表按车辆分组，当前车辆任务置顶高亮；未绑定时全部按车辆平铺。
6. 服务 Tab 展示任务管理/车务管理/维保管理/数据统计四组入口，**无「今日用车」卡片**。
7. 服务 Tab 任务管理三入口为跨车辆、按类型查询，详情只读，口径与改造前一致。
8. 交车 → 今日回顾 → 返回首页，回到地图 Tab 未绑定态，闭环成立。
9. 原有子页面、上报页、留痕规则、组件规范无回归。
